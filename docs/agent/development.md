# development — 开发规矩

> 由 AGENTS.md §真相源 触发加载:写 spec/设计/实现/交付/验收/诊断前必读。

## spec 文件是版本必须项

开工前立 `docs/spec/00NN-YPJ-MMM-slug.md`(增量节,概要设计;**文件名必带 item code**,一票多 spec 时主票号+关联票号,2026-11-13 定;此前的 `00NN-vNN-slug` 旧名不追溯),完工后补 As-built;无 spec 不开工(2026-10-08 定,V16 系补录见 0013)。**编号全局递增、一文件一号**:新文件(含子票 spec)一律取下一个新号,不用父票号加后缀(2026-11-28 定,0177-sN 共号旧约定已废止改名;最大号=最新,排序即新旧)。

## 每票实现前三件套(2026-10-09 立)

spec 增量节含:①需求(写细,含范围/非目标)②详细设计(代码级修改计划:改哪些文件、怎么改、否决的备选)③手工测试用例(供用户 build/debug 阶段执行);用户过目后才编码。**凡涉前端设计,②必须附「操作流程(状态×动作真值表)+ 页面示意图(ASCII,贴合实况)」**(2026-11-09 定,自 YPJ-164/spec 0115 起)。

## 切票边界自查(结论 ≤2 行)

本票收尾干净?下一步依赖本会话推理?handoff 会不会复述 AGENTS/专项文档已有内容?→ clear / compact / handoff 三选一,自包含默认 clear。

## 大任务先拆(2026-10-29 立,YPJ-106 复盘)

预估超一个会话、或触达文件 > 30 的实现任务,动工前先给拆分方案——按可独立合并、各自验证绿的**垂直切片**切,不按层切(层间门禁会逼你当场把下一层的活干完,拆了等于没拆)。确实不可拆的,写明理由。休止点:每个切片/阶段设「验证绿」检查点;每到绿点**主动收口**(状态落持久工件 + handoff),绝不顶着 token/时限限额往下一阶段冲。

## 格式化走工具链(YPJ-121)

backend `gradle ktlintFormat`、web `npm run format`;CI 有 format check,格式不对 build 红。行尾纪律真相源 = `.gitattributes`(默认 LF,ps1/bat/cmd CRLF)。

## 验证与停等边界(2026-11-22 澄清)

- **agent 编码阶段验证 = 代码自证**:tsc/单测/format/相关 gradle 验证,就地 commit 绿点
- **用户验收 = 环境验证**:build/debug + 手工测试 + e2e——agent 本地绿不能替代
- 验收过 → agent 开 PR → 用户审阅合并 → agent 走合并回合(workflow.md)
- 后端「验证绿」定义:`gradle build` + `integrationTest` 绿 + bootRun 能启动(临时端口验证,起后即停;integrationTest 需 Docker,CI 兕底 nightly)
- 编码完成后**停**:功能代码+测试代码写完即停,等用户 build/debug,通过后再 PR

## 手工测试用例落档(2026-11-20 定,YPJ-244 验收复盘)

除一眼可见的冒烟验证,每个任务(票)的手工测试用例落档到 `docs/testing/manual-test-cases.md` 并维护:开工时立节,交付用户时给勾选清单,验收逐条勾(`[ ]`未验/`[x]`过/`[!]`红未解,红例记台账),As-built 同步结果;历史用例不删留作回归。环境 dev 3001;验收前先确认 dev 容器跑的是含目标票代码的镜像(容器 Image sha 对比 `docker images` 最新,曾实锤旧镜像导致误报)。

**例外(2026-11-22)**:纯文档/调研票、纯结构零语义重构且 e2e 已覆盖回归、无任何 UI/行为变化的内部调整 → 可免落档,PR 描述注明理由;其余功能票一律落档。

## 诊断交付七规(2026-11-01 立,YPJ-131 复盘,P0+P1,违反=流程事故)

1. 验收 = **用户主路径**测试绿,不是实现路径绿;测试先按用户实际操作路径写。
2. 用户报 N 个症状,交付前逐条标注「已解释/已修复/仍开放」,禁止打包「都修好了」。
3. 归因必须实锤(查库/直调 API);未实锤的归因标「假设」,禁入「勿走回头路」与 handoff 结论。
4. 每个结论先设计反证探针——明确「什么证据能推翻它」,证实与证伪都做。
5. UI 双路径/状态相关行为(保存/另存、点击语义)必须写「状态×动作→行为」真值表进 spec;结果级描述不算设计完成。
6. 品味型交互(两可设计如点击语义)动工前摆两方案给用户拍板或给可点原型,agent 不代选。
7. 交用户复验前,agent 先做最小数据探针(查库/直调确认写入已发生);「测试绿」≠「数据落了」。
