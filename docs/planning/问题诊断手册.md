# 问题诊断手册(living document)

> 定位:**诊断与修复的详情**,按问题组织,无时间戳。发现新问题→新增条目;老问题有新解法/新认识→**就地修改**原条目。
> 姊妹篇:`问题处理记录.md` = 历史留痕(append-only,只记流水:日期/票号/一行症状/指向本手册编号)。
> 规矩:只有实锤(trace/查库/直调)才准写「根因」;开放问题标 ⚠。编号全局唯一,已定稿条目不改号。

## A. 集成测试环境与 Spring context

### A1(#8)全例红:Unable to find a @SpringBootConfiguration
- 症状:integrationTest 全例 `IllegalStateException: Unable to find a @SpringBootConfiguration`。
- 根因:⚠ 假设未实锤——运行期 classpath 无 main 产物;最可能 build classes 陈旧/不完整,或运行目录非本态。
- 处理:`gradle clean` 排除陈旧产物;集成测试按 skill「跑法」用 CLI(backend/ 下),不用 IDE runner。
- 预防:全灭型奇异错误先 clean 再查;复现时记录确切命令与运行目录。

### A2(#15)全例红:Spring context 起不来(itemRepository bean 创建失败)
- 症状:交付后用户跑 integrationTest 全例红。
- 根因(实锤):新增派生查询 `countByProjectObjectIdAndTypeKey`——Item 实体属性是 `type`(String),Spring Data 把 `TypeKey` 解析为路径 `type.key` → "No property 'key'"。context 启动期才爆,compileKotlin/单测(mock)均不报。
- 修复:方法名改 `countByProjectObjectIdAndType`。
- 预防:派生查询名以实体真实属性为准;新增派生查询后先跑任一集成类验 context;「单元全绿≠context 健康」。

### A3(#19)测试类全例红:APPLICATION FAILED TO START,ObjectMapper NoSuchBeanDefinition
- 根因(实锤):仓内是 Jackson 3(`tools.jackson.databind`),测试写成 Jackson 2 包名(`com.fasterxml`)——classpath 可解析编译过,容器无对应 bean,启动期才爆。
- 修复:import 统一 `tools.jackson.databind.ObjectMapper`。
- 预防:Spring Boot 4 = Jackson 3;import 前先 grep 仓内既有用法;与 A2 同族「编译过≠context 健康」。

### A4(#22)全例红:context 起不来(build report 目录无失败详情)
- 根因(实锤):V60 迁移表名写成 `projects`,真实表是单数 `project`(V1__core.sql);报错在 console 的 Caused by 链,report 目录只有 problems-report.html。
- 修复:V60 改 `ALTER TABLE project`,全量重跑绿。
- 预防:写迁移前先 grep 既有迁移的表名(Entities @Table / V1);表名单复数是本仓高频错点。
- 排障法:集成红先读 console Caused by 链,report 目录不含测试失败详情。

### A5(快照排障法,#25 抓现行配套)
- 集成红但处理器吞栈:给对应 handler 临时加 log.warn 带栈重跑,console 直出 PSQLException 与被违反约束名——一轮定位,不猜。

## B. 集成测试写法与断言

### B1(#2/#7)编译失败:`Unresolved reference 'isConflict'`
- 根因:RestTestClient 的 StatusExpect 无 `isConflict()`;仓内 409 断言房风是 `.expectStatus().isEqualTo(409)`。
- 修复:改房风写法。
- 预防:写断言前先 grep 仓内同状态码既有写法,不凭记忆写 API。

### B2(#13)ktlint 假绿:compileTestKotlin 绿但 ktlint parse 失败
- 根因(实锤):测试函数声明漏 `()`(解析级非法);compileTestKotlin 不覆盖 integrationTest source set,绿是假信号。
- 修复:补 `()`;集成侧编译自检改用 `:api:compileIntegrationTestKotlin`。
- 预防:integrationTest 改动自检用 compileIntegrationTestKotlin;新测试函数带 `()`。

### B3(#9)深夜现形的唯一红例:overdue 期望 true 实得 false
- 根因(实锤):服务 Clock=UTC(ClockConfig),测试用本地 `LocalDate.now()`(UTC+8)算「昨天」——00:00–08:00 差一天,白天跑必绿。
- 修复:测试改 `LocalDate.now(Clock.systemUTC())` 同钟。
- 预防:请求体里算「相对今天」的日期,用与服务一致的 Clock 区;涉日界断言的测试必须能过午夜。

### B4(#16)单测 404 路径红:实际返回空 DTO 未抛
- 根因(实锤):mockk relaxed 对 nullable 返回类型默认回子 mock 非 null——代码拿假 Project 走完全流程;仓内惯例是显式 `returns null`。
- 修复:补 `every { ... } returns null`。
- 预防:relaxed mock 断「应空/应未找到」路径必须显式 stub null。

### B5(#17)单测聚合顺序红:期望 task 实得 bug
- 根因(实锤):实现按字典序 `sortedBy`,bug < task;行为符合设计,断言写反。
- 修复:调换断言顺序并注明字典序。
- 预防:对有序输出写断言先推演实现给出的序。

### B6(#21)单测编译红:`returns 1 to 0` actual Int
- 根因(实锤):Kotlin infix 左结合,解析为 `(every{...} returns 1) to 0`。
- 修复:写 `returns Pair(1, 0)`。
- 预防:mockk stub 多部件值用显式构造器。

### B7(#20)集成红:建议 0 段(读缓存冲掉 FINAL 锚)
- 根因(实锤):读时缓存 upsert 无条件覆盖快照行,把 finalize 锚(capturedBy/captured_at)刷掉,单提交段永久消失。
- 修复:upsert 分支按权威优先级——finalize 锚只被新 finalize 刷新,read 只刷提交数据。
- 预防:两个机制写同一行时,先列「谁有权覆盖谁」优先级表;缓存永不倒挂覆盖业务权威。

## C. 迁移与 schema

### C1(#25)集成红:PATCH 409「数据约束冲突」且无日志
- 根因(实锤):`ck_item_activity_kind` CHECK 白名单不含新活动类型(V9 起,V13/14/16/40 均扩过);处理器吞栈导致首轮归因无证据。
- 修复:迁移扩白名单;GlobalExceptionHandler.integrity 加 log.warn 带栈(保留,归因基建)。
- 预防:新增活动类型前先 grep ck_item_activity_kind;映射 409 的处理器必须记日志。见 A5 排障法。

### C2(#26)集成红:PATCH 200 但 GET 读回 null
- 根因(实锤):合并纯函数返回 copy,调用点忘 `save`——活动日志记了但库没写。
- 修复:调用点补 save。
- 预防:变更函数返回新实体时核对「谁落库」;「活动日志记了≠库写了」。

## D. e2e

### D1(#1)project-settings 开关偶发丢失/点击无效
- 根因(实锤):「先渲染+disabled 门禁」下点击意图落在 GET settle 前 ~50ms 帧窗口被吞。
- 修复(产品):dialog 内容加载完成才渲染。
- 预防:异步加载一律「加载完成才渲染」;竞态归因走 trace+查库,单跑绿不作漂移证据(压测复现后才结案)。

### D2(#5)group-types 建 type 后 Esc 关不掉(全量必红单跑绿)
- 根因(实锤):新建成功→表单重置→按钮 disable→焦点掉 body,Escape 不进弹层子树;keylog 实锤红轮 target=BODY。
- 修复(产品):create() 重置后焦点回输入框——兼真 UX bug。
- 预防:关弹层交互的焦点依赖:重置/disable 后必显式回焦;「快照列表空」先辨陈旧帧再下结论。

### D3(#6)挂两站后第二站依据空(单跑 --debug 绿)
- 根因(实锤):测试连点两 chip 后立刻 goto,第二个在途 GET 被导航中止(status -1),PUT 未发出。
- 修复(测试):waitForResponse 等两个 PUT 落库再 goto。
- 预防:「点击触发异步写」后跳转/断言前等对应响应;POST 端单跑绿不作漂移证据。

### D4(#10)偶红:assignee 409 成员不在项目中
- 根因(实锤):GET /api/members 无 ORDER BY,按索引取到并行用例建的虚拟成员;虚拟成员须显式入池。
- 修复:milestone.spec 改用 apiAssignMe()。
- 预防:e2e 指派一律走 apiAssignMe;无序列表按索引取成员是反模式。

### D5(#4)就绪度断言错
- 根因(实锤):把「挂接数」误当「就绪度」(gateDone/gateTotal);查库实锤后判代码对测试错。
- 修复:改断言。
- 预防:断言前先回读 spec 指标口径;两可读数的 UI 文案考虑带语义。

## E. 前端契约与视图同步

### E1(#14)侧栏当前 milestone 不随级联更新
- 根因(实锤):侧栏仅 mount 时 fetch,MilestonePage 变更只刷页内 state 无广播(sprint 段已有 sprints-changed 同型解,milestone 漏)。
- 修复:变更成功后广播 milestones-changed,layout 监听重拉。
- 预防:侧栏新增段视图时,变更通知与数据拉取成对设计;「兄弟组件会自行刷新」是反假设。

## F. 流程与工具链

### F1(#11)CI e2e 红,rerun 仍红
- 根因(实锤):非测试红——CI 格式检查步骤打回(Prettier warn 指名文件)。
- 修复:本地 prettier --write → commit+push 自动重跑。
- 预防:交付前本地 `npm run format`;CI 红先读 log-failed 分辨「格式红 vs 测试红」。

### F2(#12)分支搬家 reset 基准算错,ktlint commit 被弃
- 根因(实锤):HEAD~1 落在 spec commit 而非编码 commit;force-push 前未核对父链。
- 修复:cherry-pick 回 main + reset + force-with-lease 重写。
- 预防:reset 搬家前 `git log --oneline -3` 核实父链;确认当前分支。

### F3(#18)agent 直连脚本读 legacy session.json 打错实例
- 根因(实锤):YPJ-183 会话分存后 legacy session.json 仍「活着」内容似真(dev token),脚本惯性读老路径打 prod 401。
- 修复:脚本改读 `current` 指针 → `sessions/<slug>.json`。
- 预防:外部状态结构升级后旧文件是陷阱,直连脚本一律从 current 指针出发;候选:legacy 改名 .bak(归 YPJ-183 后续)。

### F4(#24)编译红:Conflicting declarations + 参数未传
- 根因(实锤):改签名时锚点只包尾部,同名参数复制了两份。
- 修复:删重复行。
- 预防:改函数签名前先读完整签名;报「参数未传」先查同名参数重复。

### F5(#23)ktlint:测试函数名含全角冒号报非法字符
- 修复:去冒号改空格。
- 预防:backtick 测试名不用冒号(全/半角)。
