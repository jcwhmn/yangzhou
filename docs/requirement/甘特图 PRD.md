# 甘特图 PRD v2(2026-11-17,YPJ-206 研究稿)

> 替代 v1 草稿。输入:用户 6 点反馈 + 常规甘特图工具对标。收口点 = milestone「甘特图功能落地」(target 2026-12-01)。
> 数据事实:start/due = DATE 无时分;`item_status_history` 有完整状态迁移时间戳(实际线数据源);Milestone/Release 均有 `targetDate`(Release 另有 `releasedDate`)。

## 一、常规甘特图功能对标(MS Project / Asana / Jira Advanced Planning / GanttProject 通例)

| 能力域 | 通例 | 本仓现状 |
|---|---|---|
| 任务条 | start→end 横条,含当天 | 有,但宽少一天(B3) |
| **计划 vs 实际**(baseline/actual) | 计划条+实际条双层,偏移天数标注 | ❌ 无 |
| 汇总条(summary) | 父=子聚合区间 | ❌ 无(U2) |
| 里程碑 | 独立菱形,不占时长 | 仅「只有 due 的 item」画菱形,真 Milestone 实体不上图 ❌ |
| 依赖连线 | FS/SS 箭头线 | ❌ 无(只有 blocked 文字) |
| 进度 | % 或状态着色、今日线上下遮罩区分已过/未过 | ❌ 仅超期红 |
| 时间轴缩放 | 年/季/月/周/日/时 多级缩放+平移 | 月/周/日仅刻度密度,无滚动 ❌ |
| 日历 | 工作日历(工作时段/节假日),条按日历铺 | ❌ 无 |

## 二、用户 6 点反馈 → 需求映射

### R1 范围选择(用户点 1)
甘特数据源支持范围过滤:**全部 item / 看板(board) / sprint / ItemGroup**。
- 后端:`GET /gantt` 增 `?scope=board|sprint|group&scopeId=...`(缺省=全部);item 全集树序保留,过滤后孤儿父链仍须完整(祖先链不被过滤截断)。
- 前端:页头范围选择器(下拉四选+二级选具体对象)。

### R2 计划 vs 实际线 + 偏移量(用户点 2,核心增量)
- **计划条** = startDate→dueDate(现状条)。
- **实际条** = 实际开始→实际结束/今天:
  - 实际开始 = `item_status_history` 首次迁入非 START 的时间;实际结束 = 首次迁入 FINAL 的时间;未完成 = 延伸到今日线。
  - 与 YPJ-132(startedAt/completedAt 列)方向一致;本期先用历史推导,132 落库后切换数据源。
- **偏移量** = 实际结束 − 计划 due(未完成则今天 − due):行上标 `+3d`(延期绿红语义)/`-2d`(提前)。
- 展示形态:双层条(计划=细描边框条,实际=实心条叠加)或分色双行,实现期摆两方案给用户拍板(七规 6)。

### R3 拖拽编辑(用户点 3)
- 可行:PATCH `/api/items/{id}` 已支持 startDate/dueDate,权限/校验复用现有。
- 交互(常规):拖条身=整体平移(两日期同移);拖左右边缘=改单端;拖拽中浮显日期,松手 PATCH,失败回弹。
- 依赖:R6 时间轴视口先行(拖拽需要像素/天映射)。
- 约束:里程碑菱形只能拖 due;依赖不自动联动(不做 FS 自动重排,通例中也是可选项)。

### R4 日轴/工作时间轴(用户点 4,纠偏)
用户语义:「日」粒度=**一天之内的 0 点–24 点整点轴**;另需 8 小时工作制轴。这不是 YPJ-204 做的「逐日刻度」。
- `day` 档:横向一天 = 一屏宽区间,刻度 = 0:00…23:00 整点。
- 工作制轴:项目级设置(工作时段,默认 8h,如 9:00–18:00 午休扣 1h?)——**需拍板**:仅影响轴刻度显示,还是影响条按时长铺排(后者要工时数据,DATE 模型下无意义;建议本期只做刻度形态)。
- 数据边界:DATE 无时分,所有条在日轴上恒占整日/整工作段——轴形态先行,时分级排期等 DATE→TIMESTAMP 迁移另票。
- 新缩放档:年/季/月/周/日(逐日)/时(单日 24 线)六级。

### R5 Milestone 与 Release 上图(用户点 5)
- **Milestone 实体**:targetDate → 专属泳道(顶部一行)画菱形+名称;gate 型里程碑(milestone_item)同泳道标关联 item 数。in_progress 的当前里程碑高亮。
- **Release**:targetDate → 专属泳道菱形(带版本/stage 色);releasedDate → 已发布竖线标记(或菱形变实心)。
- Milestone-Release PRD US-M11(甘特泳道 defer)在此兑现,交付后回写该 PRD 状态。

### R6 时间轴视口与缩放(承 v1 U1)
- 横向滚动 + 缩放(档位见 R4);最小像素/天;今日线默认入视口。
- P0 bug 修复(承 v1):孤儿 item 兜底显示(B1)、UTC 日界统一(B2)、条宽含当天(B3)。

### 其余承 v1
- 父汇总条(子孙并集;冲突语义待拍板)、FINAL 置灰样式、依赖连线(FS 箭头)、完结过滤开关。

## 五、DATE→TIME 级迁移分析(用户点:实际管理到 time 级;建议优先处理)

### 现状与爆炸半径
- `items.start_date/due_date` = DATE;同列还有 `milestones.target_date`、`releases.target_date/released_date`。
- 触点:api(item/group/metrics/excel/project 六处 service)+ cli(Main.kt)+ web(backlog/板/详情/甘特/报表)+ e2e helpers。**domain 引擎零 LocalDate,不受影响**(硬规则保持)。

### 设计决策(建议,待拍板)

| 决策点 | 建议 | 理由 |
|---|---|---|
| 存储类型 | `timestamp`(LocalDateTime 墙钟,**不带时区**) | 排期语义是「本地的几点几分」;用 Instant 会把时区搅进每个比较和展示,无收益 |
| 范围 | **只迁 item 两列**;Milestone/Release 保持 DATE | 里程碑/发布是日期级事件,时间无管理语义;控制爆炸半径 |
| 迁移 V66 | `ALTER TABLE items ALTER start_date TYPE timestamp USING start_date::timestamp`(两列同型);可空性不变 | 存量默认 00:00 |
| 契约兼容 | 请求/响应同时接受 `yyyy-MM-dd`(旧客户端/CLI 不断)与 ISO datetime;响应统一发 datetime | 纯增量兼容 |
| date-only 默认值(信任边界填充) | start=date-only → 当日 `workdayStart`;due=date-only → 当日 `workdayEnd` | 与工作日历语义闭环;00:00 会造成「当天到期即逾期」类伪问题 |
| 工作日历 | project settings 增 `workdayStart/workdayEnd`(默认 09:00/18:00);节假日不在本期 | 排期时长计算与日轴(R4 工作制轴)都靠它 |
| 时长换算 | due = start + estimate,按工作日历跨日铺(如 09:00 起 10h → 当日 18:00 + 次日 10:00) | 兑现「结束=开始+预估时长」纪律的系统化 |
| overdue 口径 | now > due(改用 LocalDateTime.now() 注入 Clock) | 原「date < today」废止 |

### 工作量评估(粗估)
- 后端:迁移+实体+DTO 解析兼容+overdue/指标/excel 适配 ~1 票;工作日历设置+时长换算 ~1 票;CLI `items schedule` 时间级参数随 YPJ-207 合并。
- 前端:日期控件换 datetime(分钟粒度)+甘特日轴 0–24 点随 R4;~1 票。
- 建议拆 2~3 张票,**排在 S1(P0 修复)之后、S5(计划/实际线)之前**——实际线的「偏移量到小时」才有意义。

## 八、sprint 拉入排期硬校验 + 依赖感知占位自动排期(用户点:预估进 sprint 必须)

### 校验规则(落地在 group-membership 拉入时,groupType=sprint)
- 硬前置:item 必须已有预估(estimateValue+Unit),否则 409「进 sprint 须先填预估」。
- startDate 录入优先级:
  1. **请求显式携带** → 用请求值;
  2. **依赖可推**(item 有 dependsOn 且全部前置已有 dueDate,无冲突)→ 占位自动录入:`start = max(前置 due + 1天, 今天)`(按工作日历顺延到工作日);
  3. **无依赖** → 占位自动录入 `start = 今天`(工作日历顺延);
  4. 均不可得(依赖存在但前置无日期)→ 409,提示先排前置。
- dueDate 一律系统算:`start + 预估时长`(工作日历跨日铺),请求携带的 due 仅作覆盖。
- 响应回填最终起止,前端拉入后立即可见(甘特计划线数据源闭环)。
- 立票:挂 V31(甘特计划线的前置)。
