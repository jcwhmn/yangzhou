# 甘特图 PRD v3(2026-11-21 重写,客观需求版)

> 替代 v2 研究稿(历史过程见 git)。本文只陈述「系统应当如何」:渲染规则、排序、时间轴、交互、表单互算,按分支穷尽,供实现与验收对照。开放决策集中在 §12,拍板后并入正文。

## 1. 目标与定位

- 单项目树形甘特视图:逐行展示 item 的**计划时间线**与**实际时间线**,核心读数是「实际与计划的差」。
- 只读视图(拖拽编辑另票);数据源 = 项目 items + 状态迁移史;入口 `/p/{key}/gantt`。

## 2. 数据源与语义

| 数据 | 来源 | 语义 |
|---|---|---|
| startDate / dueDate | item 字段(timestamp,本地墙钟) | 计划起止;均可空 |
| estimateValue / Unit | item 字段(hour/day/week) | 预估工时;换算 hour=v、day=v×工作窗、week=v×5×工作窗;非必填 |
| actualStart | 状态史首次迁出 START | 实际开始 |
| actualEnd | 状态史迁入 FINAL | 实际完成;迁出 FINAL(返工)后保留 |
| anchorDate | 依赖锚:FS = 最晚前置的 due(前置无 due 取 start);显式 start 永远优先 | 无 start 时的计划落点 |
| checklistDone/Total | item 清单 | 进度遮罩 |
| workdayStart/End | 项目设置,默认 09:00–18:00;周六日照算(节假日历另票) | estimate 换算与 due 铺算的工作窗 |
| overdue | now > due 且非 FINAL | 超期 |

- **due 铺算** = start + estimate 按工作窗跨日铺(如周五 16:00 起 8h → 下周一 16:00 前后)。铺算只用于算 due(日期),**不用于决定条长**(见 §7.2)。

## 3. 行模型

- **父行** = item 树内有子孙的行;**叶行** = 其余;渲染与排序按树深度优先(子随父)。
- **折叠**:折叠父 → 隐藏全部后代;折叠钮在标题列;折叠时汇总条显「+N」徽标(N=全部后代数,任意深度)。
- **未排期折叠组** = 同时满足的叶行:无 start、无 due、无依赖锚、无 actualStart、父链无 group 开始锚(§4)。渲染在双面板上方折叠区(默认收起),不进主面板。
- 父行恒入主面板;子树无任何时间数据时汇总条不画(空行)。

## 4. 叶行渲染真值表

计划层分型(互斥完备):锚 = startDate ?? 依赖锚。

- **case1** 无 estimate、无锚
- **case2** 有 estimate、无锚
- **case3** 无 estimate、有锚
- **case4** 有 estimate、有锚
- **due-only** 无 start、无依赖锚、有 due → 里程碑菱形,不进矩阵
- **借锚** = case1/2 的兜底:group 开始锚 = 父链上溯最近祖先的 startDate;全链无 → 未排期组

### 4.1 计划层(未开始/进行中/完成同形)

| case | 渲染 |
|---|---|
| case1 | 全链有 group 锚 → 蓝点 @ group 开始;全链无 → 未排期组 |
| case2 | 全链有 group 锚 → 蓝条 @ group 开始,长 = estimate 钟表时长(§7.2);全链无 → 未排期组 |
| case3 | 有 due → 蓝条 锚→due;无 due → 蓝点 @ 锚 |
| case4 | 蓝条 start→due(due 缺省由 estimate 铺算,互算语义一般已存储) |
| due-only | 琥珀菱形 @ due,零时长 |

### 4.2 实际层(叶行专属)

| 状态 | 渲染 |
|---|---|
| 未开始 | 无实际层 |
| 进行中 | **单条覆盖模型(进行中恒一条线,无第二条)**:有计划条(case2/case3 有 due/case4)→ 计划条蓝为底,黄覆盖叠上 = actualStart→min(今天,条尾);无计划条(case1、case3 无 due)→ 黄条 actualStart→今天(case3 保留计划位蓝点) |
| 完成 | **双条模型(计划蓝上 + 实际绿下,上下错开,完成行无黄色)**:case1 仅绿条;case2 上蓝(estimate 钟表长)+ 下绿(actualStart→actualEnd);case3 蓝点 + 绿条;case4 双条 |
| 直建 FINAL | actualEnd 有而 actualStart 无 → 完成时刻零宽绿点 |
| FINAL 后返工 | 见开放决策 D5 |

- **清单完成率遮罩**画在实际层:进行中在黄覆盖段/黄条,完成在绿条(宽 = 完成率)。
- 超期进行中:计划条红(§9),覆盖满条。
- 有 actualEnd 而当前非 FINAL:实际条止于 actualEnd,不延伸到今天(现状;D5)。

## 5. 父行渲染

- 父行只画**汇总条**,不画自有条/点、不画实际条。
- **汇总条 = 子树包络**:左端 = min(全部子孙 startDate??dueDate,全部子孙 actualStart)——子孙实际开始早于一切计划日期时,包络对齐到实际(父行开始随最早子任务重算;纯渲染口径,不改库数据);右端 = max(全部子孙 dueDate),是否并入 actualEnd 见 D4。
- 汇总条中性色,折叠时显 +N 徽标。

## 6. 排序

**排序锚 = 渲染锚**(行序与可见条位置一致):

| 行 | 排序锚 |
|---|---|
| 叶行 | startDate ?? actualStart(仅 actual 的行按实际起点排,不垫尾) |
| 父行 | 子树包络最早端(计划 start??due ∪ 实际 actualStart) |
| 未排期组 | 置尾,组内按 number |
| due-only / 借锚行 | 见 D2 |

同锚按 number 兜底。

## 7. 时间轴

### 7.1 轴形态
- **24h 钟表线性轴**:条长 ∝ 钟表跨度;跨夜条含夜间钟表时长;小时刻度 0–24 墙钟。
- 缩放承诺:范围窗满辐 48h 时,8h 条 = 1/6 视口宽。

### 7.2 条长来源(互斥,⚠实现前请复核)
1. **due 权威条**(case3 有 due / case4 / due-only 菱形零宽):长 = start(锚)→due 钟表跨度。
2. **estimate 条**(case2 借锚,无 due 可依):长 = estimate 换算钟表时长(8h → 8h 跨度),与实际条同单位直接可比(计划 8h vs 实际 10.3h → 实际条更长);**不做工作窗铺算**——借锚点可能在窗外,铺算会把 8h 画成 >1 天,标称与条长脱钩。
- 已知读法差异:铺算 due 的行(16h estimate → due 跨 2 工作窗)条长 = due−start 钟表跨度 > 16h;due 是存储权威值,条长如实反映。

### 7.3 视口与缩放
- 连续 pxPerDay 缩放(非档位);上限 2400 px/天;缺省视窗下限 3 px/天。
- fit 全数据适配;今日线默认入视口、贯穿全高;中心导航 ±1 天;范围窗快捷按钮;缩放中心锚定;滚动/视窗存档恢复。
- 刻度行 2–3 行自适应(月/周/日/时按像素密度门控)。

## 8. 界面与交互

- **双面板**:标题列(灰底右边线;按内容自然宽、超宽列内底部横滚;标题单行 noWrap 可点进详情;列宽拖拽 + localStorage 记忆 + 双击重置)+ 甘特区(缩放横滚)。**行高恒定 44px,标题行与图行逐行对齐;行高不随内容浮动,对齐破坏 = 缺陷**。
- **hover 卡**:标题、状态、负责人、计划起止(到分钟)、实际起止(到分钟)、预估工时(小时)、实际工时(完成 = actualStart→actualEnd 状态史时长;小时)、锚点说明(依赖落位/group 借锚)。
- **图例**:黄覆盖 = 已流逝(实际色覆盖计划)/ 蓝点 = 依赖锚点落位 / 中性条 = 父汇总 / 菱形 = 里程碑 / 红 = 超期;无灰(完成行不置灰)。
- **范围过滤**:全部 / 看板 / ItemGroup / milestone / release,二级选对象;过滤后孤儿父链完整(祖先不被截断)。
- **已完成折叠组**(采纳待实现):FINAL 行默认折叠进「已完成(N)」组,可展开。
- 工具栏:缩放 ±、fit、今日、范围窗、中心导航、面板分隔条(拖拽调标题列宽)。

## 9. 偏移徽标与视觉系统

- **偏移徽标**:条尾 = (actualEnd ?? 今天) − due;延期红、提前绿;due 无值不显;0 值与单位规则见 D3。
- **三色系统**(全页唯一色彩承载):蓝 = 计划;黄 = 进行中实际;绿 = 完成实际。
- 红 = 超期计划条与延期徽标;琥珀 = 里程碑菱形;汇总条中性灰蓝;今日线 info 蓝;完成行不置灰。

## 10. 表单互算(due ⇄ estimate 二选一,后改者为准)

- 有 start:改 estimate → due 按工作窗铺算写回;改 due → estimate 按工作历时数反推写回(档位转自由小时,警告)。
- 两值同 PATCH → 都生效,冲突仅警告不互算;显式清 due 且 estimate 有 → due 立即铺算回填 + 警告;无 start 只存 estimate 不铺算(警告「无开始日期,预估未推算」)。
- 反推换算 0h → 条零时长最小 3px;due<start → 400。
- PATCH 响应可带 warnings,前端 Snackbar toast 展示。

## 11. sprint 拉入排期校验(groupType=sprint 拉入时)

1. 硬前置:item 必须已有 estimate,否则 409。
2. start 优先级:请求显式 > 依赖可推(max(前置 due+1 天, 今天) 按工作日顺延)> 无依赖 = 今天 > 均不可得 409。
3. due 一律系统算 = start + 预估时长(工作日历铺);请求携带 due 仅作覆盖;响应回填最终起止。
