## 1. 文档目的与范围

### 1.1 目的
定义单项目树形甘特图的功能、数据语义、时间计算、渲染、排序、交互、契约约束及验收标准,作为产品、前后端开发与测试的共同依据。

### 1.2 产品目标
甘特图逐行展示 Item 的**计划时间线**与**实际时间线**,帮助用户识别计划与实际的偏差(「与计划的差」是本视图的核心读数)。

### 1.3 本期范围
- 单项目树形甘特视图;计划/实际时间线;父子汇总、折叠、排序。
- 依赖锚点与 Group Anchor 借锚;时间轴缩放、导航、范围过滤。
- Hover 卡、图例、偏移徽标;Estimate 与 Due 表单互算;sprint 拉入排期校验。

### 1.4 非目标
拖拽编辑、Milestone/Release 泳道、依赖连线(FS 箭头)、基线快照、关键路径、FS 自动联动重排、资源负载泳道、多项目 Roadmap、导出图/PDF、工作制设置面板与节假日历(见 §3.2,后续 item)。

### 1.5 入口与权限
- 入口 `/p/{key}/gantt`;只读视图,时间编辑走 Item 表单等既有入口。
- 数据源:项目 Items、item 树、状态迁移史、项目设置(工作制)、依赖关系。

## 2. 术语与定义

| 术语 | 定义 |
|---|---|
| Item / Leaf / Parent | 工作项;无子孙为叶;有子孙为父 |
| 计划时间线 | 由 startDate/dueDate/Estimate/锚点推导的计划层元素(条/点) |
| 实际时间线 | 由状态迁移史推导的实际层元素(条/点) |
| Estimate | 预估工时,单位 hour/day/week |
| 依赖锚(Dependency Anchor) | FS 依赖下最晚前置的 due(前置无 due 取 start) |
| Group Anchor(借锚) | case1/2 叶行向父链上溯借用的最近祖先 startDate,作为计划落点 |
| 包络(Envelope) | 一组可见时间元素的最早/最晚时间界;父行汇总条、排序锚、fit 共用 |
| 单条覆盖模型 | 进行中行的实际层画法:计划条蓝为底,黄覆盖叠上,无第二条 |
| 双条模型 | 完成行的实际层画法:计划条(蓝)在上,实际条(绿)在下 |
| 工作制 | 项目级每日工作时长设置(当前缺省 24h,无 weekend 休息日) |
| FINAL | 最终完成状态 |

## 3. 数据与业务语义

### 3.1 Item 字段
| 字段 | 来源 | 语义 |
|---|---|---|
| startDate / dueDate | Item 字段(本地墙钟) | 计划起止,可空 |
| estimateValue / estimateUnit | Item 字段(hour/day/week) | 预估工时,非必填 |
| actualStart | 状态史首次迁出 START | 实际开始 |
| actualEnd | 状态史迁入 FINAL | 实际完成;返工后保留(§6.6) |
| checklistDone / Total | Item 清单 | 进度遮罩 |
| 依赖(dependsOn) | Item 关系 | FS 语义,推导依赖锚 |

**时区口径(2026-11-21 评审 P1-5):** 本版本为**单时区部署假设**——排期字段为不带时区的本地墙钟(按部署实例时区输入与展示),状态史为 UTC Instant、展示转本地;今日线/overdue/排序均按同一时区解释。不处理 DST;多时区支持另票。

### 3.2 工作制(2026-11-21 拍板)
- **当前缺省 = 24 小时制,无 weekend 休息日**(每日 00:00–24:00 全为工作时段,周六日照算)。
- 工作制设置面板(24h/8h/10h、上下午、每日起止、weekend 休息日)为**后续 item**;落地前一切换算按 24h 缺省执行。
- **同刻度原则:计划与实际永远共用同一时间刻度,条长比例在计划条与实际条之间保持一致,不混用刻度。** 24h 工作制下,铺算=纯钟表加法。
- 未来工作制(8h/10h、上下午、每日起止、weekend)的铺算/跨窗/实际工时扣减规则 = **设计原则,不构成本期验收要求**;落地时由排期语义保证 start/due 落在工作窗内以维持同刻度,细则随工作制设置 item 定义。

### 3.3 Estimate 换算(24h 工作制下)
- hour = v 小时;day = v × 24h;week = v × 7 × 24h(=168h,无休息日语义,2026-11-21 拍板)。
- due 铺算 = start + estimate(24h 制下即钟表加法);**铺算只用于算 due,不用于决定条长**(条长见 §9.2;24h 制下两值相等)。

### 3.4 状态时间
- actualStart = 首次迁出 START(永久保留);actualEnd = **最近一次**迁入 FINAL(2026-11-21 评审 P1-4 定;多次返工取最近,完整迁移记录保留供 Hover 返工历史)。
- 当前状态非 FINAL:按 §6.2 进行中渲染,历史完成时刻只进 Hover;当前状态为 FINAL:用最近一次 FINAL 画绿条。

### 3.5 Overdue
`overdue = now > dueDate && 状态非 FINAL`;超期计划条红色。

## 4. Item 时间线模式与父子关系

### 4.1 叶 Item
显示自身计划时间线(§5)与实际时间线(§6)。

### 4.2 父 Item
只显示 Summary Bar(§7);不画自有计划条/点、不画自有实际条。

### 4.3 父行自有日期作废(2026-11-21 拍板)
- 各级父行的自有 startDate/dueDate 与自有状态史**在甘特渲染层作废**:不参与汇总条包络、排序锚、fit。
- 数据不清理、不迁移:其他视图(看板/详情)照常显示;子 Item 全部删除后,item 回归叶行,自有日期**自然恢复显示**(无需转换机制,天然可逆)。
- Group Anchor 借锚(§5.3)是唯一读取祖先 startDate 的场景:祖先日期对其自身行作废,但作为子孙的借锚来源仍有效。

### 4.4 Group Anchor 与 Parent 的关系
Group Anchor 不是 Parent 的独立时间线;它只决定符合条件的叶 Item 的计划落点,Hover 卡须能解释借锚来源。

### 4.5 删除子 Item
子孙全部删除后按叶行规则渲染:自身 startDate/dueDate **与状态迁移史**均重新参与叶行计划层与实际层渲染;不执行数据迁移或字段改写。

## 5. 叶 Item 计划时间线

### 5.1 锚点
`anchor = startDate ?? 依赖锚`;显式 start 永远优先。

### 5.2 互斥场景(计划层,未开始/进行中/完成同形)

| Case | Estimate | 锚 | Due | 渲染 |
|---|---|---|---|---|
| 1 | 无 | 无 | 无 | 全链有 Group Anchor → 蓝点 @ 借锚;否则未排期组 |
| 2 | 有 | 无 | 无 | 全链有 Group Anchor → 蓝条 @ 借锚,长 = Estimate 钟表时长;否则未排期组 |
| 3 | 无 | 有 | 有 | 蓝条 锚→due |
| 3b | 无 | 有 | 无 | 蓝点 @ 锚 |
| 4 | 有 | 有 | 有 | 蓝条 start→due(due 缺省由 Estimate 铺算,互算语义一般已存储) |

- **due-only(无 start 有 due)已废除**(2026-11-21 拍板):创建/更新时 dueDate 有而 startDate 无 → 400「须先填开始日期」(§12.5);菱形渲染规则仅为历史数据兼容保留,新数据不会再产生。

### 5.3 Group Anchor 借锚
仅用于 case1/2 兜底;借锚 = 父链上溯最近祖先的 startDate;全链无 → 未排期组;借锚来源在 Hover 卡中解释。

### 5.4 未排期折叠组(2026-11-21 评审 P0-2 修订)
**计划层与实际层均无任何可渲染时间元素**的叶 Item 才入未排期组:无 start、无 due、无依赖锚、无 actualStart、**无 actualEnd**、父链无 Group Anchor。(直建 FINAL 的完成点 §6.4 必须在主面板渲染,不得入组。)渲染在双面板上方折叠区(默认收起),不进主面板;Parent Item 恒留主面板。

## 6. 叶 Item 实际时间线

### 6.1 未开始
不显示实际层。

### 6.2 进行中(单条覆盖模型;进行中恒一条线、零徽标)
- 有计划条(case2/3 有 due/case4):计划条蓝为底,黄覆盖 = **条内已流逝段**(start→min(今天,条尾),拍板方案 A 口径);**无第二条**。
- 无计划条(case1、case3b):黄条 actualStart→今天(case3b 保留计划位蓝点)。
- 清单完成率遮罩画在黄覆盖段/黄条上。
- 超期进行中:计划条红,覆盖满条;无徽标(超期由红条表达)。

### 6.3 完成(双条模型;完成行无黄色)
上=计划层(case 照 §5.2),下=绿条 actualStart→actualEnd,上下错开;case1 仅绿条;case2 上蓝(Estimate 钟表长)+下绿;case3b 蓝点+绿条;case4 双条。徽标规则见 §11.1。

### 6.4 直接进入 FINAL
actualEnd 有而 actualStart 无 → 完成时刻零宽绿点(最小可视 3px)。

### 6.5 清单遮罩
宽 = checklistDone/checklistTotal;checklistTotal=0 不绘制(防除零);进行中画在黄覆盖段/黄条,完成画在绿条。

### 6.6 FINAL 后返工(2026-11-21 拍板:当前状态优先)
状态非 FINAL 一律按 §6.2 进行中渲染(黄条延伸到今天);上次完成时刻保留在 Hover 卡,不参与渲染。

## 7. 父行 Summary Bar 与包络

### 7.1 原则
父行汇总条必须罩住当前过滤条件下全部可见子孙的时间元素;父行不短于任何可见子孙条。

### 7.2 包络计算(2026-11-21 拍板;评审 P0-1 修订:从渲染结果反推)
- 参与者 = 当前过滤后可见的**叶 Item** 全集;各级父行自有日期与自有状态史作废(§4.3)。
- **按叶行实际渲染出的时间元素收集,不从字段分别拼凑**:每个叶行产出计划元素(条/点)与实际元素(条/点)——
  - 计划条 = 锚(start/依赖锚/Group 借锚)→(due 端[date-only 含当天] ?? 锚 + Estimate 钟表长);仅锚无长度 → 计划点(零宽,左右端均=锚);
  - 实际条 = actualStart→(actualEnd ?? 今天);仅 actualEnd → 完成点(零宽,直建 FINAL §6.4);
  - due-only 菱形(历史数据)= 零宽点位。
- 左端 = 全部元素最小时间;右端 = 全部元素最大时间;无任何元素 → 不绘制 Summary Bar(父行空行)。
- **过滤决定参与,折叠只决定展示**:被 UI 折叠(如 §10.6 已完成组)的行仍参与包络与 fit,展开/折叠不引起父条与 fit 跳变(评审 P1-6)。
- 未排期组不参与(在主面板外)。

### 7.3 三处同源
Summary Bar 包络、排序锚(§8)、fit 范围(§9.4)复用同一套包络计算,禁止各算各的。

### 7.4 外观
中性灰蓝细条;折叠时显「+N」(N=全部后代数,任意深度);展开不显徽标。

## 8. 排序

### 8.1 原则
排序锚 = 渲染锚:行序与可见条位置一致。

### 8.2 排序锚(2026-11-21 拍板)
| 行 | 排序锚 |
|---|---|
| 叶 | **min(计划层左端, 实际层左端)** = min(startDate ?? dueDate ?? 借锚位, actualStart ?? actualEnd 完成点)——行序与可见条最左端一致(评审 P1-1) |
| 父 | 子孙叶包络最早端(§7.2) |
| 未排期组 | 置尾,组内按 number |

同锚按 number 兜底。due-only 已废除,无此行型。

## 9. 时间轴与视口

### 9.1 轴形态
24h 钟表线性轴;条长 ∝ 钟表跨度;跨夜条含夜间钟表时长;小时刻度 0–24 墙钟;满辐 48h 窗时 8h 条 = 1/6 视口宽。

### 9.2 条长来源(互斥)
1. **due 权威条**(case3/4):长 = 锚→due 钟表跨度。
2. **Estimate 条**(case2 借锚):长 = Estimate 换算钟表时长(8h → 8h),与实际条同刻度直接可比;不做工作窗铺算。
- 24h 工作制下铺算 due = 钟表加法,两口径等值;未来工作制落地时由排期约束(§3.2)保持同刻度。

### 9.3 缩放与导航
连续 pxPerDay 缩放(上限 2400 px/天;**3 px/天 = 缺省视窗的下限,仅约束缺省态,显式缩放可破**);fit;今日线默认入视口、贯穿全高;中心导航 ±1 天;范围窗快捷;缩放中心锚定;滚动/视窗存档恢复;刻度行 2–3 行按密度自适应。

### 9.4 Fit 范围
fit = 当前过滤后全部可见时间元素的包络(§7.2 同源;Summary Bar 不重复扩大范围);无任何元素时用缺省视窗。

### 9.5 边界
本地墙钟语义,无 DST 处理;due<start → 400;空日期不得当 epoch/默认日期;零宽元素最小 3px。

## 10. 页面布局与交互

### 10.1 双面板
标题列(灰底右边线;按内容自然宽、超宽列内底部横滚;标题单行 noWrap 可点进详情;列宽拖拽 + localStorage 记忆 + 双击重置;初始 280px、最小 120px、无硬上限——横滚兜底)+ 甘特区(缩放横滚);标题行与图行严格对齐。

### 10.2 行高
固定 44px;行高不随内容浮动;任何对齐破坏 = 缺陷。

### 10.3 Hover 卡
标题、状态、负责人、计划起止(到分钟)、实际起止(到分钟)、Estimate(小时)、实际经过时长(完成 = actualStart→actualEnd 状态史时长,小时;实际经过时间≠实际工时,未来扣除非工作时间后再分列)、锚点说明(依赖落位/Group 借锚)、返工历史(如有)。

### 10.4 图例
黄覆盖 = 已流逝(实际色覆盖计划)/ 蓝点 = **计划锚点位**(Hover 说明显式开始、依赖锚或 Group 借锚,评审 P1-2)/ 中性条 = 父汇总 / 红 = 超期;无灰(完成行不置灰);菱形图例随 due-only 废除一并移除。

### 10.5 范围过滤
全部 / 看板 / ItemGroup / milestone / release,二级选对象;过滤后祖先链完整;**父行包络与排序按过滤后可见子孙计算**(2026-11-21 拍板)。

### 10.6 已完成折叠组(采纳待实现)
FINAL 行默认折叠进「已完成(N)」组,可展开。

### 10.7 工具栏
缩放 ±、fit、今日、范围窗、中心导航、面板分隔条。

## 11. 偏移徽标与视觉系统

### 11.1 偏移徽标(2026-11-21 拍板:仅 FINAL 显示)
| 状态 | 显示 |
|---|---|
| 未开始 / 进行中(含超期) | 不显(进行中超期由红计划条表达) |
| 完成 \|Δ\|<1h | On time(中性色) |
| 完成 1h≤\|Δ\|<24h | ±Nh(提前绿/延期红) |
| 完成 ≥24h | ±Nd(提前绿/延期红) |

Δ = actualEnd − due;due 无值不显。徽标紧贴条尾。

### 11.2 三色系统(全页唯一色彩承载)
蓝 = 计划;黄 = 进行中实际(覆盖/条);绿 = 完成实际。红 = 超期计划条与延期徽标;汇总条中性灰蓝;今日线 info 蓝;完成行不置灰。

## 12. Estimate 与 Due 表单互算

### 12.1 原则
二选一互算,后改者为准。

### 12.2 有 start
改 Estimate → due 按工作制铺算写回;改 due → 按工作制反推 Estimate(档位转自由小时,警告)。

### 12.3 同一 PATCH 两值
都生效,不互算,冲突仅警告。

### 12.4 清空 due
显式清 due 且 Estimate 有 → due 立即铺算回填 + 警告;无 start 时 Estimate 只存不铺算。

### 12.5 异常与校验(2026-11-21 拍板)
- **dueDate 有而 startDate 无 → 400「须先填开始日期」**(due-only 废除;无论 Estimate 与否)。
- due<start → 400;反推 0h → 条零时长最小 3px。
- PATCH 响应可带 warnings(前端 Snackbar toast 展示)。**契约现状 = `warnings: string[]`(中文文案,前端原文展示);code/field/severity 结构化升级另票,升级前前端不得依赖解析文案判断类型(§14)。**

## 13. sprint 拉入排期校验(groupType=sprint)

1. 硬前置:Item 必须已有 Estimate,否则 409。
2. **start 占位(2026-11-21 拍板):请求显式 start 优先;否则 start = sprint 开始时间**(实操纪律:不允许无 startDate 的 Item)。依赖感知顺延为后续增强,另票。
3. due = start + Estimate 铺算;请求携带 due 仅作覆盖;响应回填最终起止。

## 14. 错误处理与一致性
- 包络/排序/fit 必须同源计算(§7.3),前后端口径一致。
- 父子关系或过滤变更后,包络、排序、fit 重算。
- 空日期不当 epoch;checklistTotal=0 防除零;due<start 按错误契约。
- API 警告结构化,前端不得解析自然语言判断类型。

## 附录 A:关键计算原则摘要
1. 叶 Item 表达自己的计划与实际;Parent 只表达后代汇总(自有日期与自有状态史作废)。
2. 包络、排序锚、fit 三处同源,基于过滤后可见叶字段并集。
3. 计划与实际同刻度:条长比例恒定,铺算不改变比例(24h 缺省下铺算=钟表加法)。
4. Estimate 条长 = 钟表时长;due 权威条 = 锚→due 钟表跨度。
5. 显式 start 优先于依赖锚;借锚是 case1/2 的兜底而非父行时间线。
6. 状态决定实际层表达:进行中单条覆盖、完成双条、返工按当前状态。
7. 偏移徽标只属于完成行。
8. **Sprint 拉入后的 Item 必须写入 startDate**(显式优先,否则 = sprint 开始时间占位);普通 Item 允许无 startDate——计划落点按依赖锚与 Group Anchor 规则计算;dueDate 无 startDate 的请求一律拒绝(§12.5)。
9. 未决业务规则必须显式标记,不得由实现人员自行补充(本版无未决项)。
