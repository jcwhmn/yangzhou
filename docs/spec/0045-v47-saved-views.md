# 0045 — V20 / YPJ-47(+YPJ-28 合并):表格视图配置——筛选保存复用 + 列配置 Popover 重设计

> 需求源:YPJ-47(2026-10-14 立票,对标 Plane Views;票面明确「与 YPJ-28 合并为一个视图配置票实施」)。分支 `task/YPJ-47`。**本票交付后 YPJ-28 一并关闭**(同一片代码,票面语义即合并)。

## 一、需求

### 背景
表格页(`web/app/p/[key]/table`)目前:无内容筛选(只有排序);列配置 = 标题行下一排 Chip 点选,localStorage 持久。筛选条件无法保存复用;列数还会增长,Chip 行模式到头(YPJ-28 的触发条件)。

### 范围
1. **视图实体(后端)**:`project_view`,按「用户 × 项目」隔离,存 `filters`(JSONB)+ `columns`(JSONB)+ 名称;CRUD API。
2. **筛选(前端,客户端过滤)**:status / assignee / priority 三个下拉;items 本就全量在手,不过后端(数据量级不需要;后端过滤另票)。
3. **视图管理(前端)**:视图下拉(默认视图 + 已存列表)、保存/另存为(命名 Dialog)、删除;选中视图 = 应用其 filters+columns。
4. **列配置重设计(= YPJ-28)**:Chip 行收进「列配置」Popover(checkbox 列表 + 恢复默认);编号/标题恒显;默认列配置仍 localStorage 持久(现状平移),选中视图时以视图数据为准。
5. e2e:视图保存→切换→删除主链 1 例。

### 非目标
- 列排序(拖拽)——YPJ-28 候选方向,列数不多不做。
- 服务端过滤/分页。
- 看板/列表页复用视图(先表格页落地,泛化另票)。
- 视图共享/默认视图团队级。

### 验收(票面)
- [ ] 筛选可保存/命名/删除;与列配置同页管理
- [ ] YPJ-28 一并关闭(列配置 Popover 化)

## 二、详细设计

### 1. 迁移 `V33__project_view.sql`

```sql
create table project_view (
    id          bigint generated by default as identity primary key,
    object_id   uuid        not null,
    project_id  bigint      not null,
    creator_id  bigint      not null,          -- member.id,视图私有于创建者
    name        varchar(100) not null,
    filters     jsonb       not null default '{}'::jsonb,   -- {status?: uuid, assignee?: uuid, priority?: text}
    columns     jsonb       not null default '{}'::jsonb,   -- {status?: bool, ...} 同现 localStorage 结构
    created_at  timestamptz not null default now(),
    updated_at  timestamptz not null default now(),
    constraint uk_pv_object_id unique (object_id),
    constraint fk_pv_project foreign key (project_id) references project (id),
    constraint fk_pv_creator foreign key (creator_id) references member (id)
);
create index ix_pv_project_creator on project_view (project_id, creator_id);
-- 同一用户同项目视图名唯一
create unique index ux_pv_name on project_view (project_id, creator_id, name);
```

无枚举/CHECK(filters 是自由 JSON)。`AbstractApiTest.cleanDatabase()` 清单 + `project_view`(item 无 FK,序放 project 相关之后)。

### 2. persistence
- `entities.kt`:`data class ProjectView(id, objectId, projectId, creatorId, name, filters: String, columns: String, createdAt, updatedAt)`——JSONB 列映射 String(Jackson 序列化在 service 层做,与仓内 JSONB 先例一致;若现有 JSONB 实体直接用 JsonNode 则跟随)。
- repo:`ProjectViewRepository`,派生查询 `findByProjectIdAndCreatorIdOrderByCreatedAt(projectId, creatorId)`、`findByObjectIdAndCreatorId(objectId, creatorId)`。

### 3. api 切片 `view`(垂直切片:entities 已在 persistence;controller+service+DTO 同包)
- `GET /api/projects/{key}/views` → 自己的视图列表(不含 filters 内容也返回,量小)。
- `POST /api/projects/{key}/views` `{name, filters, columns}` → 409 同名;filters/columns 校验为合法 JSON 对象、大小上限(各 4KB)。
- `PATCH /api/views/{viewId}` `{name?, filters?, columns?}` → 只能改自己的;不存在/非本人 → 404(不泄露存在性)。
- `DELETE /api/views/{viewId}` → 同上。
- 权限:操作者必须是项目成员(沿 project_member 校验惯例);GET 同理。
- Controller 类级 `@RequestMapping("/api")`;OpenAPI @Tag("views")。api.http:views 区块 + 正例链(建→列→改→删)+ 负例区(同名 409、改他人 404)。

### 4. 前端表格页改造
- 新组件 `web/components/ColumnConfigPopover.tsx`:锚点按钮「列配置」,Popover 内 checkbox 列表(现 columns 数组)+「恢复默认」;替换现 Chip 行。
- 筛选行(列 toggle 原位):三个 Dropdown(status 取自项目 statuses、assignee 取自 items 去重、priority P0–P3)+ 视图控件。
- 视图控件:Dropdown(「默认视图」+ 服务端视图列表)、Button「保存」(已选视图→PATCH 覆盖;默认视图→弹命名 Dialog=POST)、「另存为」、视图旁 × 删除(确认)。
- 状态机:`filters`/`cols` 两个 state;选视图 → 两者整体替换;改动即标记 dirty(保存按钮高亮);localStorage 逻辑仅服务默认视图。
- texts.ts 新增 `t.view` 区块(中文文案)。

### 5. 测试设计
- 集成 `ViewsApiTest`(extends AbstractApiTest):建/列/改名/删;同名 409;非本人 PATCH/DELETE 404;非项目成员 403;filters 非法 JSON 400。数据库断言 JSONB 落库形状。
- e2e `view.spec.ts`:建项目→保存视图(筛选+改列)→切默认→切回视图(断言筛选生效:列表只剩预期 item)→删视图。
- 验证:`gradle build` + integrationTest;`tsc`/`next build` + flow 既有 e2e 不回归。

## 三、手工测试用例(用户 build/debug 执行)

5. 另一账号登录:看不到前者建的视图。
6. 列配置 Popover:勾选/恢复默认正常,编号/标题不在可关列表。
7. api.http views 链全过;全量 e2e 绿。
