# spec 0056 — V73 YPJ-48 ItemGroupType 动态类型

> 票:YPJ-48;PRD §6(ItemGroupType 运行时定义)/ §28.2(类型运行时 CRUD 原属 defer-until-asked,本票即"asked"后的实施)。

## ⚠ 架构边界说明(置顶)

- 本票**不动** domain 匹配引擎:ItemGroup 从不入匹配输入(领域规则 5),ItemGroupType 只是展示层/组织层配置,零引擎改动。
- **Milestone 不并入 item_group**:V28 已裁决 milestone 为独立表(PRD §9「非 ItemGroup」),本票维持;票描述中列了 milestone 是笼统提法,取与现有实现一致的读法——milestone 不参与本票。**请人复核此读法。**
- **Epic 不在本票**:当前 epic 以 item `type='goal'` 建模(web 侧栏 Epics 段即筛 goal item),不是 ItemGroup。把它 ItemGroupType 化是领域语义变更,另票。

## 一、需求

### 范围
- `item_group.type` 从硬编码字符串(现 CHECK 约束 `('sprint','release')`)收敛为**项目级运行时类型** `item_group_type`:每个项目可列出/新增/改名/删除自己的 group 类型。
- 内建类型 `sprint` / `release` 建项目时自动种子,既有项目经迁移种子;内建类型**不可删除**(sprint/release 端点语义依赖它),可改名。
- 新增通用 ItemGroup 端点:任意类型(含自定义)下建组/列组/改名/删组/成员管理(最小集:name + 可选起止日期 + planned/active/completed 状态,兼容「年/季/月/周」等时间盒型自定义组织——2026-10-18 用户补充;无 released/released_date/milestone,那是 release 专属语义)。
- 既有 sprint/release 数据零丢失:迁移只加表+种子+放开 CHECK。

### 非目标
- 不做类型级行为配置(状态流、日期必填、默认视图等)——自定义类型统一走最小语义;sprint/release 专属端点与不变量原样保留。
- 不做 ItemType(§4)运行时定义——那是 item 的 type,另票。
- 不动 View/导航配置(§20)。
- 前端仅最小支持:项目设置页的类型列表管理;侧栏不新增自定义类型段(自定义组的入口走通用端点,UI 消费另票)。

## 二、详细设计(代码级)

### 1. 迁移 `V35__item_group_type.sql`
```sql
create table item_group_type (
    id          bigint generated by default as identity primary key,
    object_id   uuid        not null,
    project_id  bigint      not null,
    type_key    varchar(20) not null,
    name        varchar(50) not null,
    builtin     boolean     not null default false,
    created_at  timestamptz not null default now(),
    updated_at  timestamptz not null default now(),
    constraint uk_item_group_type_object_id unique (object_id),
    constraint uk_item_group_type           unique (project_id, type_key),
    constraint fk_item_group_type_project   foreign key (project_id) references project (id)
);
-- 既有项目种子(仅内建两类;CHECK 保证现存 type 只有这两值)
insert into item_group_type (object_id, project_id, type_key, name, builtin)
select gen_random_uuid(), id, 'sprint', 'Sprint', true from project;
insert into item_group_type (object_id, project_id, type_key, name, builtin)
select gen_random_uuid(), id, 'release', 'Release', true from project
where exists (select 1 from item_group g where g.project_id = project.id and g.type = 'release');
alter table item_group drop constraint ck_item_group_type;
```
- `item_group.type` 保持 varchar 不动(存量数据零迁移);service 层校验 type 必须在项目 `item_group_type` 中。
- 种子 release 仅对用过 release 的项目(否则给它塞一个用不上的类型;新建项目则两粒都种)。

### 2. 新切片 `api/grouptype/`
- `GroupTypeController` / `GroupTypeService`,`@RequestMapping("/api")`,资源段 `/projects/{key}/group-types`。
- 实体 `ItemGroupType` 进 `persistence/entities.kt` + repository 进 `repositories.kt`(`findByProjectIdOrderByCreatedAt`、`findByProjectIdAndTypeKey`)。
- DTO:`GroupTypeDto(typeKey, name, builtin)`;请求 `CreateGroupTypeRequest(typeKey, name)` / `UpdateGroupTypeRequest(name)`。
- 规则:typeKey `[a-z][a-z0-9-]{1,19}`,项目内唯一(冲突 409);builtin 不可删(409)、不可改 key;删除前校验该类型下无组(有则 409)。
- ProjectService.create 种子 sprint/release(内建)。

### 3. 通用组端点(`grouptype` 切片内,最小集)
- `GET /projects/{key}/groups?type=<typeKey>` 列该类型组;`POST /projects/{key}/groups` 建组(name + typeKey 必填);`PATCH /projects/{key}/groups/{groupId}` 改名;`DELETE` 删组(连同 membership 级联删除,复用现组删除逻辑若有,否则本票补)。
- status/日期:自定义组可传可选 startDate/endDate 与 status(planned/active/completed,缺省 planned);不暴露 released 状态/releasedDate/milestoneId。
- Sprint/Release 端点改动:创建时经 `findByProjectIdAndTypeKey` 取类型行,取不到 409(理论不可达,builtin 不可删,防御用);其余逻辑零改动。

### 4. 否决的备选
- **item_group.type 改 FK 到 item_group_type.id**:动存量列+所有查询,收益仅数据库级完整性;service 校验已够,否决。
- **类型行为配置列(状态流 JSON 等)**:投机抽象,第一个自定义类型用户出现前不需要,否决。
- **Milestone/Epic 并入**:见置顶说明,否决(本票)。

### 5. 测试
- 单测优先(规矩:单测优先,integration 只留关键路径):GroupTypeService 单测(Fake repo:typeKey 校验/唯一冲突/builtin 保护/删除时存在组 409)。
- 集成(关键路径):group-types CRUD + 通用组 CRUD 一条链;迁移后既有 sprint/release 仍可用(建项目→种子→sprint 端点照常)。
- 新表 `item_group_type` 记入 AbstractApiTest cleanDatabase 清单(读 skill 后按其格式加)。
- e2e:不改(前端仅设置页最小管理,如实现则补 1 条 smoke;倾向本票不动 e2e)。
