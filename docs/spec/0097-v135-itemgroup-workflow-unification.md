# spec 0097 — YPJ-137 ItemGroup 一层重构:Workflow 泛化统一生命周期,去 sprint 硬编码

> 票:YPJ-137(YPJ-105 子票,V27)。设计真相源:`docs/designs/ItemGroup.md`(2026-11-03 用户手写,含 PlantUML)。
> 本 spec 覆盖设计文档 **case 2「1 level」**;case 1(两层,YPJ-110/111/112 线)与 case 3(no itemGroup,用户再想)另票。
> v3(2026-11-03):transitions 内嵌 JSON 化(用户裁决:依附 status 的不独立建表);迁移号修正(V44 已占用)。

## ⚠ 架构破坏 / 契约变更(置顶,显要标注)

1. **item workflow 契约破坏**:status 的 `isStart/isFinal/isInProgress` 三布尔 → 单一 `statusType`(START/FINAL/ACTIVE 枚举,每状态恰属一类)。Workflow API DTO、web WorkflowEditor、看板/flow 判定同步改。
2. **status_transition 表删除**(item 侧既有表):出边迁移内嵌 `status.transitions` JSON;**group 侧不建 transition 表**(同原则)。Workflow API 的 transition 管理、web WorkflowEditor 同 PR 改。
3. **sprint 专属端点删除**:`/sprints*`、`PUT /items/{id}/sprint` 下线,统一 `/groups*` + `PUT /items/{id}/group-membership`。web/CLI 同 PR 改造,无兼容层(yz 命令面不变,内部映射)。

自由迁移语义保留(出边空数组 = 全放行,领域规则 3 不变)。

## 一、需求

### 范围(设计文档 §description 对齐)

1. **Workflow 统一模型**(item 与 group 共用抽象):
   - Status 带 `statusType`:每状态恰属 START / FINAL / ACTIVE 一类;workflow 至少各一个 START 与 FINAL。
   - Transition 内嵌于 status(`transitions` JSON 数组):`{"function":"start","target":"<同type内status名>"}`;处于某状态时可用动作 = 该状态 transitions 的 function 集。
   - Action 用**预定义函数集**:`start / complete / switch / forward / backward / cancel`(自定义动作实现 defer;`displayName/icon` 前端按 function 渲染,文案外置;**不建 action 实体表**)。
2. **item workflow 迁移**:三布尔 → `status_type` 单列;`status_transition` 表聚合为 `status.transitions` JSON 后删除。
3. **GroupWorkflow 挂 ItemGroupType**:类型级定义状态机(ItemGroupType 即 workflow 宿主,组实例只存 currentStatus);内建类型种子,自定义类型默认模板;组状态变更改为**动作触发**(白名单),不再自由 PATCH。
4. **统一 ItemGroupService/Controller**:吸收 SprintService 全部业务 + 0056 通用组端点;**删 SprintService/SprintController**;`Sprint` 只是组名,「开始 Sprint」只是动作名。
5. **语义泄漏收口**(吸收原 YPJ-113 目标):assignItem/create 初始归属/自动挂载/hasLive 四处筛 `type='sprint'`;sprint+release 归属按类型正交(PRD §7.3)。
6. **侧栏 Epic 段移除**(case 2 明确);sprint 段数据源走通用组端点。

### 非目标

- 多层嵌套(case 1,YPJ-110/111/112)。
- release 收编重构:本票不碰 release 契约(ReleaseService/Controller 原样;其 `released` 语义已是 type 化,非硬编码重灾区)。收编另票。
- workflow 编辑 UI(workflow 定义经 API 可配,web 只读展示);自定义动作函数;no-itemGroup 场景(case 3)。
- Milestone(独立表裁决不变)、Epic item 树语义(goal type 不变,只是侧栏段移除)。

## 三、详细设计

### 3.1 迁移(两片各自落地;JSON 先例:V43/V44 view 用 text 列存 JSON + 实体 String,沿用)

**S1 — `V45__workflow_status_type.sql`**(注:V44 已被 view_col_order 占用,新迁移自 V45 起):

```sql
alter table status add column status_type varchar(20) not null default 'ACTIVE';
update status set status_type = 'START'  where is_start;
update status set status_type = 'FINAL'  where is_final;
update status set status_type = 'ACTIVE' where status_type = 'ACTIVE'; -- 其余(含三值全 false 如 In Review)默认 ACTIVE
alter table status drop column is_start;
alter table status drop column is_final;
alter table status drop column is_in_progress;
alter table status add constraint ck_status_status_type check (status_type in ('START','FINAL','ACTIVE'));

-- 出边迁移内嵌为 JSON(依附 status,不独立建表;存量迁移无动作概念 → 全回填 switch)
alter table status add column transitions text not null default '[]';
update status s set transitions = coalesce((
    select jsonb_agg(jsonb_build_object('function', 'switch', 'target', ts.name) order by ts.name)
    from status_transition t join status ts on ts.id = t.to_status_id
    where t.from_status_id = s.id), '[]'::jsonb)::text;
drop table status_transition;
```

- transitions 项形:`{"function":"start","target":"<同project内status名>"}`;target 用 **name 引用**(project 内 status 名唯一),service 写入时校验存在性(DB 层不校验 JSON 内引用,与 0056「varchar + service 校验」同哲学)。
- entity:Status + `statusType` + `transitions: String`(JSON 字符串,沿 col_order 模式);service 层序列化/校验(function ∈ 预定义集)。
- 同一状态既 is_start 又 is_final(脏数据)→ FINAL 覆盖写在 START 之后;集成测试加存量无脏行断言(探针先行)。
- 预置模板(ProjectService.defaultStatuses)同步:To Do=START,In Progress/In Review=ACTIVE,Done=FINAL。

**S2 — `V46__group_workflow.sql`**:

```sql
create table group_status (
    id            bigint generated by default as identity primary key,
    object_id     uuid        not null,
    group_type_id bigint       not null,
    name          varchar(50) not null,
    status_type   varchar(20) not null,
    transitions   text        not null default '[]',
    position      int         not null default 0,
    created_at    timestamptz not null default now(),
    updated_at    timestamptz not null default now(),
    constraint uk_group_status_object_id unique (object_id),
    constraint uk_group_status_type_name unique (group_type_id, name),
    constraint fk_group_status_type foreign key (group_type_id) references item_group_type (id) on delete cascade,
    constraint ck_group_status_status_type check (status_type in ('START','FINAL','ACTIVE'))
);
```

- **group_status_transition 不建表**(用户裁决:transition 依附 status,非独立实体)——出边内嵌 `transitions` JSON,结构与 item 侧完全一致。
- 不建 GroupWorkflow 实体表:ItemGroupType 即 workflow 宿主(类型 1→1 workflow),group_status 行即其内容。
- **种子(迁移内,存量项目)**:对每个 `item_group_type` 行按 type_key 种(种子行含 transitions):
  - `sprint`:planned(START,[start→active])/active(ACTIVE,[complete→completed, backward→planned])/completed(FINAL,**transitions=[]** 终态护栏)。
  - `release`:planned(START,[complete→released])/released(FINAL,[])。released_date 副作用仍由 ReleaseService 写(本票 release 不碰)。
  - 自定义类型:planned(START)/active(ACTIVE)/completed(FINAL)三态全连通 switch(与现状通用端点「任意改」一致,零破坏)。
  - 新建类型(ProjectService.create / group-types POST)同步种默认模板。
- `item_group.status` 保留 varchar;service 校验值命中该组 type 的 group_status 集。
- **迁移排序依赖**:S1 的 V45 先于 S2 的 V46 合并落库。

### 3.2 后端

**新增 `api/itemgroup/` 切片**(ItemGroupController + ItemGroupService + GroupWorkflowService):
- 类型管理(从 grouptype 迁移改名):`GET/POST /projects/{key}/group-types`、`PATCH/DELETE /projects/{key}/group-types/{typeKey}`;**新增** `GET /projects/{key}/group-types/{typeKey}/workflow`(status 集+内嵌出边,供动作渲染)。
- 组 CRUD(吸收 sprint + 0056 通用组):`GET /projects/{key}/groups?type=`(全类型或按类型)、`POST /projects/{key}/groups`、`GET/PATCH/DELETE /projects/{key}/groups/{groupId}`。PATCH 仅 name/日期(status 改走动作端点)。
- **动作端点**:`POST /projects/{key}/groups/{groupId}/actions/{function}`——查 currentStatus.transitions,无匹配 function → 409「当前状态无此动作」;leader guard 沿 sprint 现状。
- 组成员:`GET /projects/{key}/groups/{groupId}/items`;`PUT /items/{itemId}/group-membership {groupId|null, groupType}`——按组类型替换该类型未完成归属(sprint 与 release 正交,PRD §7.3)。
- board/backlog 迁入:`GET /projects/{key}/board`(active sprint 组 items)、`GET /projects/{key}/backlog`(谓词筛 type='sprint')。
- **删除**:`api/sprint/` 整包;`api/grouptype/` 整包(并入 itemgroup);persistence 的 Sprint 专属方法随 repository 收敛。
- **ItemService 收口**:create 的 sprintId 参数只认 type='sprint' 组(404 语义不变);自动挂载 `firstOrNull { it.type=='sprint' && statusType ACTIVE }`;hasLive 按 type 判;ItemDto.sprintId/sprintName 组装筛 type('releaseId/Name' 已是,对齐)。
- WorkflowService(S1):StatusDto isStart/isFinal/isInProgress → `statusType`;transition 增删改内部读写 `status.transitions` JSON(对外 TransitionDto 形状保持 from/to/function,存储形态变化对 API 透明);`assertTransitionAllowed` 保留(item 看板拖拽语义不变,不走动作),内部改读 JSON 出边。

### 3.3 Web(S3)

- sprint/[id]/page.tsx:「开始/完成」按钮改为读 type workflow 出边渲染(completed 无按钮=历史保留,现状一致)。

## 五、手工测试用例(用户 build/debug 阶段)

1. dev 环境(3001):既有项目 sprint 段照常显示,开始/完成按钮行为不变(数据零迁移)。
2. 看板拖拽(直接迁移)照常;Workflow API:GET statuses 返回 statusType + transitions;PATCH statusType / transitions 生效。
3. sprint 页「开始」→ POST actions/start → 状态 active;重复开始 → 409;完成后再开始 → 409(终态无出边)。
4. 建自定义类型 `phase` → 建组 → 组详情可见默认三态;switch 动作任意切换。
5. item 挂 sprint A → 再挂 release R → 两者共存;PUT group-membership 换 sprint B → release R 不丢。
6. PUT group-membership 传不存在组 → 404。
7. 开始无组 item → 自动挂最早 active **sprint**(自定义 active 组不再误挂);item 在 active release → 自动挂 sprint 不再被抑制。
8. 侧栏:Epics 段消失;Sprints 段照常;CLI `sprints move/list`、`items assign` 行为不变。
