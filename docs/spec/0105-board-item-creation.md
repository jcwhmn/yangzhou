# 0105 — 看板创建 item:完整需求与决策(YPJ-104)

> 主题:在看板创建 item 的完整需求——item 去向、归属、激活与新建组交互、取消语义。本节只写「要什么」与「为什么这么定」;「怎么实现」(端点、执行顺序、失败路径)全部在 §二设计。

## 一、需求

### 1.1 行为矩阵(看板创建 item,提交那一刻)

| # | 项目状态 | item 去向 | 交互 |
|---|---|---|---|
| S0 | 项目未配置 level-1 组类型 | 创建后 item 上看板;全站不出现组概念字样 | 无 |
| S1 | 进行中的组恰 1 个 | 创建并挂入该组 | 无 |
| S1m | 进行中的组 ≥2 | 创建并挂入用户选定的组 | 选择弹窗 |
| S2 | 无进行中组,计划中的组恰 1 个 | 激活该组,创建 item 并挂入 | 确认弹窗(展示组名) |
| S2m | 无进行中组,计划中的组 ≥2 | 用户选定一个组,激活并挂入 | 选择+确认弹窗 |
| S3 | 有组类型,但无非完成态组实例(0 实例或全部已完成) | 新建一个组实例并激活,创建 item 并挂入 | 确认弹窗+名称输入(默认名=类型名+序号,可改) |

参照:Backlog 页创建 item = 入池不入组(Backlog 页自身语义,不走本矩阵)。

### 1.2 不变式(任何场景成立)

1. **必进看板**:创建成功的 item 立即在看板可见。
2. **必进组**:项目有 level-1 组类型时,新建 item 必恰归属一个非完成态组——不存在「在看板却无归属」的游离 item。
3. **互斥**:item 不同时出现在看板和 Backlog。
4. **确认制**:激活组、新建组是可见的项目状态变化,必须经用户确认,不静默代做。

### 1.3 需求决策(拍板与理由)

| # | 决策 | 理由/来源 |
|---|---|---|
| D1 | 必进看板 | 建完不可见=隐身;2026-11-06 手工实测照亮后拍板 |
| D2 | 必进组(有组类型时) | 用户 2026-11-06:有非完成态组时,item 不能同时在看板和 Backlog → 新建 item 唯一合法落点是组 |
| D3 | 多进行中组由用户选 | 归属是用户意图,不代选 |
| D4 | 无进行中→**强制激活一个并挂入,无「放入但不激活」次选项** ⚠待过目 | 用户拍板「应该要激活一个,进入那个组」;确认步保留以防误触激活的状态变化 |
| D5 | 无非完成态实例→**确认式新建组**(默认名=类型名+序号,可改) ⚠待过目 | 静默建组违背确认制;纯引导打断创建流且 item 悬置;确认式平衡两者 |
| D6 | 弹窗取消=**放弃整个创建**(item 不落库,标题保留输入框) ⚠待过目 | 游离非法→无「暂不」;用户未确认落点前不应落数据 |
| D7 | Backlog 页建 item 入池不入组 | Backlog 语义即未入组池 |
| D8 | 无组类型项目无组概念(onBoard 兜底) | 0101 铁律:UI 不得出现组概念字样;不能替用户建类型 |
| D9 | 术语:需求与界面文案一律「组」;组状态中文名=进行中/计划中/已完成 | 0101 案B 延伸;数据层状态字面量与实现层类型键例外 |
| D10 | 关联交互:详情页把 item 挂入计划中组且无进行中组 → 提示激活;取消=挂载生效但不激活 | item 已有归属、无游离问题,取消语义与看板创建不同 |

### 1.4 非目标

- 静默自动建组/激活(违背确认制)
- 存量游离 item 自动迁移
- 并发同名建组消解、自定义工作流出边缺失特判(设计节降级标注)
- 看板之外的其它创建入口改造

## 二、设计(实现层;可引用既有设施)

### 2.1 执行顺序:组先行,item 后行

S3 全链:查组列表(防重+算默认名)→ 建组 → 激活 → 建 item(带组归属)。S2/S2m 从激活步起。item 最后建,且建 item+挂入为后端同事务(负例不落库)→ **任何失败点均无游离 item**:

| 失败点 | 落点 | 游离 item |
|---|---|---|
| 建组失败 | item 未建;标题保留;可重试 | 无 |
| 激活失败 | 组留起点态;item 未建;重试时同名组复用 | 无 |
| 建 item 失败 | 组已激活(空进行中组合法);可重试 | 无 |

- 防重:提交前查组列表,同名组存在则复用不重建(组名无唯一约束,重名无害)。
- 并发边界(标注不处理):并发同名建组→同名两组,多进行中组选择弹窗天然兜底。
- 自定义 workflow(标注):起点→进行中出边缺失致激活失败 → 降级:组留起点态、item 照常挂入(补集看板仍可见)+报错提示。

### 2.2 复用设施(零后端改动)

组列表/建组/组状态动作/归属挂入既有端点;S0 的 onBoard 标志既有端点(0099);选择弹窗复用多进行中组「放入哪个组」既有形态。前端触点:`app/p/[key]/page.tsx`(建item 流程改为前置决策树,替代现行「建后补挂」)、`lib/texts.ts`、e2e `board-item-creation.spec.ts`。

### 2.3 对现行实现的替换说明

现行分支上已实现的 v1 流程(先建 item→弹窗补挂/游离 onBoard)被 §1.1 矩阵整体替代:决策前置到创建前,游离 onBoard 仅剩 S0 合法使用。详情页挂载提示(D10)已实现,保持不变。
