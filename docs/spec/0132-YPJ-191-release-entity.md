# spec 0132 — YPJ-191:Release 独立实体与 REST CRUD(US-R1)

> PRD:`docs/requirement/Milestone-Release PRD.md`(v1.2 已定稿)。前置:YPJ-165(spec 0131)已拆除旧 Release 组实现。
> 领域拍板(2026-11-15,本票开工前用户确认):
> - **Release = 交付事件,Stage = 其成熟度属性,不是独立实体/状态机**。Alpha/Beta/RC1/RC2 各是一次独立 release,`stage` 只是属性维度,与 `status`(发了没有)正交。
> - **Version 不做实体**:release 上加 `version`(string 可空)作归组维度;真需要版本线管理时再升级为词表/外键(数据不丢)。
> - **stage 封闭枚举**(方案 A):`alpha | beta | rc | ga`,DB CHECK;显示词外置文案层(可显「阿尔法/贝塔」等),code 永不翻译。序号(RC1/RC2)不建模,靠 name 区分。
> - **stage/version 均可空**——无成熟度阶梯的发布(热修包等)合法。

## 一、需求

### 范围(本票)

- `release` 独立表(与 milestone 同构形态)+ Flyway 迁移。
- REST CRUD:`GET/POST /api/projects/{key}/releases`、`PATCH/DELETE /api/projects/{key}/releases/{releaseId}`。
- 状态机:`planned → released`(单向终态);发布动作可带 `releasedDate`(缺省 = 今天,Clock 注入)。
- 终态冻结(§5.1):released 后改名/改日期/改 stage/再发布/删除一律 409。
- leader guard:写操作(create/update/delete)`LeaderGuard.requireLeader`。
- api.http 新增 Release 区块(test 环境);entities.puml 同步。

### 非目标(另票)

- item 挂接/不变量(US-R3,叉表 `release_item`)→ 本票删除守卫中「有成员拒删」暂不生效(无成员机制,planned 可直接删);R3 落地后补守卫。
- 前端面板/发布按钮(US-R2/R4)、侧栏、设置开关。
- 事后补建(US-R5:create 即 released)——本票 create 一律 planned。
- 逾期徽标(US-R7)、完成率(US-R8)、变更留痕(US-R6)。
- milestone 删除终态守卫(§12.5)——搭本主线相邻票。

### 真值表(状态 × 动作,PRD §5.1 + 本票裁剪)

| 当前状态 | 动作 | 结果 |
|---|---|---|
| planned | PATCH name/targetDate/version/stage | 200 |
| planned | PATCH status=released(+可选 releasedDate) | 200,releasedDate 空则 = 今天 |
| planned | PATCH status=其它值 | 400(非法值)/ 409(非法迁移) |
| planned | DELETE | 204(本票无成员机制) |
| released | PATCH 任何字段 | 409(终态冻结) |
| released | DELETE | 409 |

## 二、详细设计

### 迁移 `V63__release.sql`(新文件)

```sql
create table release (
    id          bigint generated by default as identity primary key,
    object_id   uuid          not null,
    project_object_id uuid   not null,
    name        varchar(100)  not null,
    version     varchar(50),
    stage       varchar(10),
    status      varchar(20)   not null default 'planned',
    target_date date,
    released_date date,
    created_at  timestamptz   not null default now(),
    updated_at  timestamptz   not null default now(),
    created_by_object_id uuid,
    updated_by_object_id uuid,
    constraint uk_release_object_id unique (object_id),
    constraint fk_release_project  foreign key (project_object_id) references project (object_id),
    constraint ck_release_stage    check (stage in ('alpha', 'beta', 'rc', 'ga')),
    constraint ck_release_status   check (status in ('planned', 'released'))
);
create index ix_release_project on release(project_object_id);
```

形态对齐 V41 后的 milestone(project_object_id FK + 审计 FK 列)。`RELEASE` 是 Postgres 非保留字,可直用。

### persistence

- `Entities.kt`:`Release`(@Table("release")),字段同表;`@CreatedDate/@LastModifiedDate/@CreatedBy/@LastModifiedBy` 同 milestone。
- `Repositories.kt`:`ReleaseRepository : CrudRepository<Release, Long>`,`findByProjectObjectIdOrderByCreatedAt` / `findByProjectObjectIdAndObjectId`。

### api 切片 `yangzhou.api.business.release`(ReleaseController + ReleaseService 同文件两 DTO)

- `POST`:name 必填(trim 非空,400);stage/version 可空,stage 不在枚举 → 400;targetDate/releasedDate `LocalDate.parse` 失败 → 400。create 一律 `status=planned`。
- `PATCH`:released 终态任何编辑 → 409;status 迁移白名单 `planned→released`,其余 409;`status=released` 时 `releasedDate` 请求带则用之,否则 `LocalDate.now(clock)`。
- `DELETE`:released → 409。
- `GET list`:planned 在前(targetDate asc nulls last,创建序),released 在后(releasedDate desc)。
- leader guard:三个写方法 `leaderGuard.requireLeader(key)`(项目无 leader 则放行,同现有 R2 语义)。
- DTO:`ReleaseDto(releaseId, name, version, stage, status, targetDate, releasedDate, createdAt)`;`CreateReleaseRequest(name, version?, stage?, targetDate?)`;`UpdateReleaseRequest(name?, version?, stage?, status?, targetDate?, releasedDate?)`(null=不动,空串=清空,同 milestone 语义)。徽标/完成率字段不进本票 DTO(R7/R8 另票加)。

### 连带动词

- `AbstractApiTest.cleanDatabase`:审计置 null 清单与 delete 清单各加 `release`(milestone 之后、project 之前)。
- `docs/architecture/entities.puml`:加 release 实体(只画领域字段)。
- `backend/script/api.http`:新区块「Release」(8082;节内自建前置)。

### 否决的备选

- stage 序号 `stage_seq` 建模:拍板不做(见上),name 区分。
- create 直建 released(合并 US-R5):切票边界,本票不做。
- 复用 item_group 机制:PRD §0 已架构回退,禁止。

## 三、手工测试用例(用户 build/debug 阶段执行;api 8082 / api.http Release 区块)

1. 建普通 release:name="1.0",targetDate=未来某日 → 201,响应 status=planned。
2. 建 stage release:name="1.0 RC2",version="1.0",stage="rc" → 201。
3. 非法 stage=dev → 400;name 空 → 400;targetDate="x" → 400。
4. 发布:PATCH status=released(不带 releasedDate)→ 200,releasedDate=今天;带 releasedDate=指定日 → 用指定日。
5. 终态冻结:对 released PATCH name → 409;DELETE → 409。
6. 删 planned → 204;list 排序 planned 前 released 后。
7. leader guard:非 leader 成员 token 写操作 → 403。
