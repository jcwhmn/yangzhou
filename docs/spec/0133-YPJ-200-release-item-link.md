# spec 0133 — YPJ-200:US-R3 item 挂接(release_item 叉表 + 不变量 + 删除守卫)

> PRD v1.2 §6 US-R3、§12.4;前置 YPJ-191(spec 0132,PR #218 已合)。

## 一、需求

### 范围

- `release_item` 叉表(镜像 milestone_item 形态:弱引用无 FK,uk 挡重)。
- 挂/摘端点:`GET/PUT /api/items/{itemId}/release-membership`,body `{ "releaseId": uuid|null }`(null = 摘),返回 `{ "releaseId", "releaseName" }`(当前归属真相)。
- 不变量(PRD §12.4):同 item 至多属一个**未终态** release → 违反 409;历史多行自然保留(挂过 1.0 RC1(released)再挂 RC2 合法)。
- 终态冻结(§5.1):released 的 release 不可挂摘 → 409。
- 删除守卫补全:release 删除时若有成员 → 409(本票起生效;spec 0132 遗留项)。

### 非目标

- item 详情 UI 下拉(US-R2 前端票);release 成员清单端点(R2/R8 需要时加);批量挂接/自动规则(defer,§12.4)。

### 真值表(挂接动作 × release 状态)

| 动作 | 目标 release 状态 | 结果 |
|---|---|---|
| 挂(releaseId=X) | planned | 200;若 item 已属另一 planned → 409 |
| 挂(releaseId=X) | released | 409(终态冻结) |
| 挂(releaseId=X) | 不存在/跨项目/软删 item | 404/400 |
| 挂(releaseId=X) | 已挂同一个 X(幂等) | 200 原样返回 |
| 摘(releaseId=null) | 无挂接 | 200 {null,null} |
| 摘 | 挂在 released release 上(历史行) | 200——只删 planned 行,released 历史行永不碰(挂接真相只看 planned;PRD「不可摘」由 released 行不可动保证) |

## 二、详细设计

### 迁移 `V64__release_item.sql`

```sql
create table release_item (
    id          bigint generated by default as identity primary key,
    object_id   uuid not null,
    release_object_id uuid not null,
    item_object_id    uuid not null,
    created_at  timestamptz not null default now(),
    constraint uk_release_item_object_id unique (object_id),
    constraint uk_release_item unique (release_object_id, item_object_id)
);
```

(milestone_item 同款:无 FK,挂接为弱引用,清理走代码路径。)

### persistence

- `Entities.kt`:`ReleaseItem`(releaseObjectId/itemObjectId,@CreatedDate createdAt;无审计列,同 milestone_item)。
- `Repositories.kt`:`ReleaseItemRepository`:`findByItemObjectId` / `findByReleaseObjectId` / `deleteByReleaseObjectId` / `findByItemObjectIdIn`。
- cleanDatabase:delete 清单加 `release_item`(release 之前)。

### api(release 切片内新增端点,controller/service 各加方法)

- `PUT /api/items/{itemId}/release-membership`(挂/摘,请求经 ItemService 校验 item 存在;不设 leader guard——与 board-membership 一致,成员均可挂摘)。
- 校验序:item 存在(404)→ releaseId 非空时 release 存在且属同项目(404)→ 目标 release planned(409)→ 不变量预检:该 item 现有挂接行中,落在其它 planned release 上 → 409(列出去哪个冲突)。
- 摘:找到 item 当前挂在 released release 的行 → 409;planned 行删除。
- 返回 `{releaseId, releaseName}`(查当前 live 挂接;无 → 双 null)。
- `GET` 同路径:只读返回同形状。

### 连带动词

- `docs/architecture/entities.puml`:ReleaseItem 实体 + Release/Item 关系;api.http 新增挂/摘区块(自含前置:建项目建 release 建 item);spec 0133 本文件。
- 否决的备选:FK 硬约束(milestone_item 已裁弱引用,保持同构);挂接计数进 release DTO(R8 再说)。

## 三、手工测试用例(api.http 8082)

1. 挂 item 到 planned release → 200 回 {releaseId, releaseName}。
2. 再挂同一 release → 200 幂等。
3. item 挂 A(planned)后挂 B(planned)→ 409,提示冲突 release。
4. 挂到 released release → 409。
5. releaseId=null 摘 → 200 {null,null};再摘 → 200 幂等。
6. 摘挂在 released release 上的 item → 409(用 released release 挂接历史行;另建 planned 挂接验证正向)。
7. 删有成员的 planned release → 409;摘空后删 → 204。
