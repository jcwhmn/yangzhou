# spec 0164 — YPJ-216 sprint 拉入排期守卫(SRS)

> 预估 8h。需求类文档一律 SRS 格式(2026-11-21 定);本文件为单一真相源,票面(YPJ-216)真值表与本文件冲突时以本文件为准。

## 一、目的与范围

**目的**:item 被拉入 sprint(timed level-1 组)时,保证其具备可执行排期——杜绝「无预估」「无起止」的悬浮票进入 sprint 交付流。

**范围内**:
- 拉入时的预估校验(项目开启「预估必填」时缺失即拒绝;未开启则放行);
- 有预估时起止日期的决策序与铺算;
- 甘特图对无预估/无开始票的缺省画图规则(§4.6);
- 四个拉入入口(§三)的行为规格与错误呈现;
- 幂等重拉(对已是成员的票再次拉入)的语义。

**范围外**:
- 存量悬浮票的一次性清洗、无预估票的中档占位、无开始票的 sprint 开始占位(→ YPJ-264;占位落点为输入框 placeholder,不写值,守卫硬校验不变);
- 已完成 sprint 的成员变更(历史不可变,既有规则);
- 非 timed 组(release/epic)的挂载。

## 二、术语

| 术语 | 定义 |
|---|---|
| 拉入 | 使 item 成为某 sprint 组成员的用户动作(四途径见 §三) |
| 守卫 | 拉入时执行的排期校验+铺算逻辑,后端单点 `ItemService.applySprintPullSchedule`,四途径共用 |
| timed 组 | groupType.timed=true 的 level-1 组(含 sprint;自定义 timed 组同纪律) |
| 工作时刻 | workMode=work 时:周末→下周一窗起;当日窗前→窗起;当日窗后→次工作日窗起。workMode=wall 时:钟表原样 |
| 预估 | estimateValue + estimateUnit 成对(缺失任一 = 无预估) |
| 预估必填 | 项目设置 estimateRequired=true;此时无预估禁止拉入 sprint |
| 缺省预估 | 甘特画图用:票无预估时取项目预估刻度「中(m)」档的数值+单位,仅用于绘制,不写回票 |
| 悬浮票 | 在 sprint/看板中但无 start/due 的 item(拉入不再要求有预估,甘特按缺省画图,不产生不可绘悬浮) |

## 三、数据语义与拉入途径

守卫挂在唯一后端入口 `ItemService.applySprintPullSchedule(item, explicitStart?, explicitDue?)`,四个用户入口收敛到两条端点:

| # | 入口 | 端点 | 后端路径 | 批量 |
|---|---|---|---|---|
| ① | item 详情页「Sprint」下拉选组 | `PUT /api/items/{id}/group-membership` | `ItemGroupService.replaceMembership` | 单 |
| ② | backlog 页 item 行「拉入看板」 | `PUT /api/items/{id}/board-membership {onBoard:true}` | `ItemGroupService.boardMembership`(自动挂最早 active;无 active → 最早 planned 并激活) | 单 |
| ③ | 看板页「拉入看板」多选对话框 | 逐条 `PUT board-membership`(同②) | 同② | 多 |
| ④ | sprint 页「拉入 item」多选对话框 | 逐条 `PUT group-membership`(同①) | 同① | 多 |

补充:
- 途径①④的移出(groupId=null)不走守卫;FINAL 态组拒绝挂载(既有规则);
- 途径②③自动挂组规则:最早 active,无则最早 planned 并激活(不产生「无 sprint 可挂」409);
- item 创建时直挂 sprint(`ItemService.create` 带 sprintId)与拉入同纪律,走守卫。

## 四、守卫规则与分支真值表

### 4.1 预估校验

| 项目设置 estimateRequired | 票无预估 | 结果 |
|---|---|---|
| true | 是 | **409**(「拉入 sprint 须先填预估时长(estimateValue + estimateUnit)」),成员行不落库,日期不变 |
| true | 否(有预估) | 继续排期决策(4.2/4.3) |
| false | 是 | **放行拉入**;无预估 → 不铺算起止(§4.6 甘特缺省画图),存量日期原样保留 |
| false | 否 | 继续排期决策(4.2/4.3) |

### 4.2 start 决策序(有预估时;首个命中即用)

| 序 | 条件 | start 取值 |
|---|---|---|
| 1 | 请求显式携带 start | 显式值 |
| 2 | item 已有 startDate(存量) | 存量值(视为已显式排期,不重排) |
| 3 | 有前置依赖且最晚前置有 due | 最晚前置 due + 1min 的下一工作时刻 |
| 4 | 有前置依赖但全部未排期 | **409**(「前置依赖均未排期,无法推导开始日期;请先排前置或显式给开始日期」) |
| 5 | 无前置依赖 | 当前时刻的下一工作时刻(now 钳制,保证 due 不落过去) |

### 4.3 due 决策

| 条件 | due 取值 |
|---|---|
| 请求显式携带 due | 显式值 |
| item 已有 dueDate(存量) | 存量值 |
| 其余 | `WorkdayCalculator.dueFrom(start, 预估工时)` 按项目工作窗铺算(week=7 天口径) |

校验:start > due → 400;日期有变化时记 `dates_changed` 活动留痕。

### 4.4 甘特缺省画图(无预估/无开始的票)

甘特图渲染时对缺失值取缺省,**仅用于绘制,不写回 item 数据**:

| 缺失 | 缺省取值 | 效果 |
|---|---|---|
| 预估 | 项目预估刻度「中(m)」档数值+单位 | 按 spec 0151 分型正常画条(长度=缺省预估铺算),不落「无长度」分型 |
| 计划开始时间 | 所在 sprint 的开始时间(sprint 无开始时间→组开始/现时刻,沿用既有链) | 从 sprint 开始画到「开始+缺省预估」 |
| 两者都缺 | 上两则叠加 | 从 sprint 开始画缺省长度条 |

### 4.5 幂等重拉

票已是目标 sprint 成员时再次拉入(早退分支,不产生重复成员行):**仍执行守卫**。存量无日期 → 补铺(4.2 序 2 起命中存量则原样保留);无预估 → 409。

### 4.6 错误呈现(前端,四途径均适用)

409/400 的统一错误 message 必须对用户可见,禁止静默吞错:

| 途径 | 呈现位置 |
|---|---|
| ①④ | 表单/对话框错误区红字 |
| ② | 页面错误区红字 |
| ③ | 对话框列表顶部红字,对话框不关;批量中任一条 409 → 中止,已成功票保留,用户修正后重试 |

## 五、验收标准

### 5.1 分支覆盖(集成测试)

- [ ] 无预估拉入 → 409,成员行与日期均不落库
- [ ] 有预估无前置 → start=now 钳工作时刻(不早于 now-1min),due=start+预估铺算,due 在未来
- [ ] 显式 start/due → 双显式生效,不被覆盖
- [ ] 显式 start 无 due → due 按铺算补齐
- [ ] 前置可推 → start=最晚前置 due 后的下一工作时刻
- [ ] 前置全未排 → 409
- [ ] 幂等重拉:存量成员无日期 → 补铺;存量成员无预估 → 409
- [ ] workMode=work 周五晚拉入 → start=下周一窗起(跨周末)

### 5.2 四途径手工验收(用户主路径)

- [ ] ①详情下拉:estimateRequired 项目无预估 → 错误可见;非必填项目无预估 → 拉入成功;有预估 → 拉起窗/铺日期
- [ ] ②backlog 行拉入看板:必填+无预估 → 页首红字、票留 backlog;其余 → 上板+自动挂 sprint
- [ ] ③看板多选拉入:必填项目含无预估票 → 对话框内红字、不关框、好票保留;其余 → 全部上板
- [ ] ④sprint 页拉入:同③语义;已是成员票重拉 → 按守卫语义补铺/保留
- [ ] 甘特:无预估票按「中」档缺省画条;无开始票从 sprint 开始画;均不写回票数据
- [ ] 回归:拉入后 overview/看板/甘特无「立刻超期」的票
