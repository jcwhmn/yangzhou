# spec 0164 — YPJ-216 sprint 拉入排期守卫 · 软件需求规格说明书(SRS)

> 需求类文档一律 SRS 格式(2026-11-21 定);配套设计见 `docs/spec/0164-YPJ-216-design.md`(怎么做)。两文件同票同号,需求变更先改本文件。

## 一、目的与范围

**目的**:item 被拉入 sprint 时保证可执行排期——用户能拉、拉了能画、画了不假超期。

**范围内**:
- 拉入时的预估校验(项目开启「预估必填」时缺失即拒绝;未开启则放行);
- 有预估时起止日期的决策序与铺算;
- 甘特图对无预估/无开始票的缺省画图规则(§4.4);
- 四个拉入入口(§三)的操作与结果、错误可见性;
- 对已是 sprint 成员的票重复拉入的语义。

**范围外**:
- 编辑框的无预估/无开始输入占位(→ YPJ-264);
- 存量悬浮票的一次性清洗(→ YPJ-264);
- 归属变更(进/出 sprint、离 backlog)的日志留痕(→ YPJ-263);
- 已完成 sprint 的成员变更(历史不可变,既有规则);
- 非 timed 组(release/epic)的挂载。

## 二、术语

| 术语 | 定义 |
|---|---|
| 拉入 | 使 item 成为某 sprint 组成员的用户动作(四途径见 §三) |
| timed 组 | 开启了时间纪律的组类型;本守卫对全部 timed level-1 组生效,不限 sprint 字面 |
| 工作时刻 | 工作制(work)项目:周末→下周一窗起;当日窗前→窗起;当日窗后→次工作日窗起。墙钟制(wall):钟表原样 |
| 预估必填 | 项目设置「estimate 必填」;开启后无预估的票不得拉入 sprint |
| 缺省预估 | 甘特画图用:票无预估时取项目预估刻度「中(m)」档的数值+单位,仅用于绘制,不写回票 |
| 悬浮票 | 在 sprint/看板中但无 start/due 的 item;拉入不再要求有预估,甘特按缺省画图,不产生不可绘悬浮 |

## 三、拉入途径与操作结果(需求)

把 item 从 backlog 拉入 sprint 共四个用户入口。四途径的拉入结果遵循同一套守卫规则(§四);差异只在操作方式与错误呈现位置。

### 途径①:详情页选 Sprint(单票)

- **操作**:打开 item 详情,在「Sprint」下拉选目标组(清空下拉 = 移出)。
- **结果**:
  - 校验通过 → 票入组;挂 planned 组 → 弹拉起窗(激活/暂不);挂 active 组 → 票进看板;
  - 校验拒绝 → 错误消息在详情页错误区红字可见,票不入组、日期不变。

### 途径②:backlog 页行内「拉入看板」(单票)

- **操作**:backlog 列表行点「拉入看板」。
- **结果**:
  - 校验通过 → 票出 backlog、进看板,自动挂最早进行中的 sprint(无进行中 → 最早计划中的 sprint 并激活);
  - 校验拒绝 → 页面错误区红字可见,票留 backlog。

### 途径③:看板页「拉入看板」(多选)

- **操作**:看板页点「拉入看板」→ 对话框勾选 backlog 票 → 点「完成」。
- **结果**:
  - 勾选票逐条按途径②语义拉入;
  - 任一条校验拒绝 → 拉入中止,错误消息显示在对话框内(列表顶部),对话框不关;已成功的票保留;修正后重试或取消。

### 途径④:sprint 页「拉入 item」(多选)

- **操作**:sprint 页点「拉入 item」→ 对话框勾选(候选 = backlog + 本 sprint 成员)→ 点「完成」。
- **结果**:
  - 勾选票逐条入组;校验拒绝 → 错误消息在对话框错误区可见,已成功票保留;
  - 候选中已是本 sprint 成员的票:勾选状态未变化的不再发拉入请求。

### 共同约束

- 任一途径的校验拒绝消息必须对用户可见,禁止静默失败(操作后无任何反馈);
- 校验拒绝的票不产生成员关系、不改变日期。

## 四、守卫规则(需求,全途径一致)

### 4.1 预估校验

| 项目设置「预估必填」 | 票无预估 | 结果 |
|---|---|---|
| 开 | 是 | **拒绝拉入**(提示先填预估),成员关系与日期均不产生 |
| 开 | 否(有预估) | 继续排期(4.2/4.3) |
| 关 | 是 | **放行拉入**;不铺算起止(甘特按 §4.4 缺省画图),票的存量日期原样保留 |
| 关 | 否 | 继续排期(4.2/4.3) |

### 4.2 开始时间决策序(有预估时;按序首个命中)

| 序 | 条件 | 开始时间取值 |
|---|---|---|
| 1 | 本次操作显式给了开始时间 | 显式值 |
| 2 | 票已有开始时间(存量) | 存量值(视为已排期,不重排) |
| 3 | 有前置依赖且最晚前置有截止 | 最晚前置截止之后的首个工作时刻 |
| 4 | 有前置依赖但全部未排期 | **拒绝拉入**(提示先排前置或显式给开始日期) |
| 5 | 无前置依赖 | 当前时刻的首个工作时刻(保证截止不落过去,不假超期) |

### 4.3 截止时间决策

| 条件 | 截止取值 |
|---|---|
| 本次操作显式给了截止 | 显式值 |
| 票已有截止(存量) | 存量值 |
| 其余 | 开始时间 + 预估时长,按项目工作窗逐日铺算 |

附加规则:开始 > 截止 → 拒绝;起止发生变化时写入变更日志。

### 4.4 甘特缺省画图(无预估/无开始的票)

甘特对缺失值取缺省绘制,**仅用于画图,不写回票数据**:

| 缺失 | 缺省 | 绘制效果 |
|---|---|---|
| 预估 | 项目预估刻度「中(m)」档数值+单位 | 正常画条(长度 = 缺省预估铺算),不落入「无长度」形态 |
| 计划开始 | 所在 sprint 的开始时间(sprint 无开始 → 既有锚点链) | 从 sprint 开始画到「开始+缺省预估」 |
| 两者皆缺 | 上两则叠加 | 从 sprint 开始画缺省长度条 |

### 4.5 幂等重拉

对**已是目标 sprint 成员**的票再次拉入(不产生重复成员行):仍执行 §4.1–4.3——无预估且必填 → 拒绝;有预估且无日期 → 补铺;日期齐备 → 原样保留。

## 五、验收标准

### 5.1 守卫分支

- [ ] 预估必填项目 + 无预估拉入 → 拒绝,成员关系与日期均不产生,错误消息可见
- [ ] 非必填项目 + 无预估拉入 → 成功入组,日期不变
- [ ] 有预估无前置 → 开始=当前时刻的首个工作时刻(不早于当前),截止=开始+预估铺算,截止在未来
- [ ] 显式开始/截止 → 双显式生效,不被覆盖
- [ ] 显式开始无截止 → 截止按铺算补齐
- [ ] 前置可推 → 开始=最晚前置截止后的首个工作时刻
- [ ] 前置全未排期 → 拒绝并提示
- [ ] 幂等重拉:存量成员无日期 → 补铺;存量成员无预估且必填 → 拒绝
- [ ] 工作制项目周五晚拉入 → 开始=下周一窗起(跨周末)

### 5.2 四途径操作验收(用户主路径)

- [ ] ①详情下拉:必填项目无预估 → 错误可见;非必填 → 拉入成功;有预估 → 拉起窗/铺日期
- [ ] ②backlog 行拉入看板:必填+无预估 → 红字、票留 backlog;其余 → 上板+自动挂 sprint
- [ ] ③看板多选拉入:必填项目含无预估票 → 对话框内红字、不关框、好票保留;其余 → 全部上板
- [ ] ④sprint 页拉入:同③;已是成员票重拉 → 按 4.5 语义
- [ ] 甘特:无预估票按「中」档缺省画条;无开始票从 sprint 开始画;均不写回票数据
- [ ] 回归:拉入后 overview/看板/甘特无「立刻假超期」的票
