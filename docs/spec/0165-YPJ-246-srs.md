## 三、需求

### 3.1 需求基准

<!-- v1 原始输入为用户 2026-11-25 口述需求(措辞存档于 handoff/票面评论),正文以下述客观规则为准 -->

行底色与条色双载体:状态靠行底色扫读,计划/实际/超期靠条色细读;底色弱于条色。

### 3.2 底色规则(数据语义)

行底色 = 该 item **当前状态**的 StatusType 分类映射;两列(标题格+时间轴区)同色;悬停 `action.hover` 叠加其上;底色**弱于**条色(条是细读层、底色是扫读层):

| StatusType | 底色 | 色值 | 语义呼应 |
|---|---|---|---|
| START(起点,如 To Do) | 中性灰蓝 tint | `#EEF2F6` | 冷/未动 |
| FINAL(终态) | 淡绿 tint | `#E7F5EC` | 呼应绿=完成 |
| ACTIVE(进行,多状态) | 琥珀浓淡 n 档(n=ACTIVE 状态数) | 浅→深 5 阶色板按档取色,见下 | 呼应黄=进行中 |

浓淡分档:档数 = 项目 ACTIVE 状态个数 n(1/2/更多皆可,不固定)。ACTIVE 状态按 `position` 升序取序号 i∈[0,n),色 = 色板[floor(i × 5 / n)]。色板 5 阶浅→深:`#FFF8E1` / `#FFF2CD` / `#FFEDB8` / `#FFE7A3` / `#FFE28E`;n=1 只用最浅,n=2 取浅+中,n=3 即浅/中/深三档;序号越大越深 = 越靠后工序。n>5 时相邻状态可能同色,属异常多状态场景,接受。色值允许实现时 ±色阶微调(同项目各档保持可辨),变更须回写本表。

### 3.3 分支真值表(行 × 类型 → 底色)

| 行类型 | statusType | 底色 | 备注 |
|---|---|---|---|
| 叶行(普通 item) | START | 灰蓝 tint | |
| 叶行 | ACTIVE | 琥珀浓淡档 | 档数=ACTIVE 状态数 n;档=按状态 position 升序序号 |
| 叶行 | FINAL | 淡绿 tint | v4「完成行不置灰」兼容:是着淡绿非置灰 |
| 父行(item 有子孙) | 任意 | **不着色(透明)** | v4 拍板「父行自有状态史不作渲染参与」;父行视觉由汇总条+标题表达 |
| 未排期组头/桶行 | — | 透明 | 弱化(§3.5) |
| 已完成组头(YPJ-245) | — | 透明 | |
| 里程碑/Release 行 | — | 透明 | 其状态(planned/…)非 item StatusType,不混用 |
| 表头/刻度行 | — | 既有 grey 体系 | 不动 |

### 3.4 父行视觉降权

- 汇总条:高饱和橙 `warning.main` → **中性灰蓝 `#94A3B8`**,不透明度 0.75,高度 8→6px;
- 父行标题:字重 600(叶行 400),无底色;
- 折叠「+N」徽标维持贴条尾(现状已对)。

### 3.5 信息密度

- **缩放记忆**:用户显式缩放(±/fit 后的 ppd)写 localStorage(`yz-gantt-ppd`,全局单值);重进甘特页有记忆则用(夹紧 [GANTT_MIN_PPD, MAX_PPD]),无记忆走现状 fit;
- **标题悬停全显**:标题格文字悬停时原生 tooltip 显完整标题(现状:noWrap+列内横滚,无 tooltip);
- **未排期组弱化**:组头去底色、文字 `text.secondary`、默认保持现有展开状态不变(默认收起列为开放决策)。

### 3.6 图例浮层

工具栏「图例」按钮 → Popover 浮层:底色三分类(含浓淡含义)+ 条五色(计划蓝/进行黄/完成绿/超期红/汇总灰蓝)+ 今日线。内容即 v4 §11.2 + 本票 §3.2 复述,不新增语义;替代底部文字图例的查找成本(现状无图例组件)。
