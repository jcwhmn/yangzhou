# 0166 — YPJ-238 看板列内 item 手工排序(方案 B:看板视图级 board order,spec=需求+设计合一)

> 票:YPJ-238(看板列内 item 手工排序;用户拍板方案 B 2026-11-26)
> 上游:ItemGroup PRD(看板 Phase);YPJ-233 甘特行序与本票无关联(甘特按 start 排,不消费 board order)。

## 一、目的与范围

看板 status 列内的 item 顺序可由用户手工拖拽排定并持久化;排序是**看板视图级记忆**(方案 B:项目 × item 粒度),与组/sprint 归属脱钩——换组、rollover 后顺序不跟随。

### 1.1 非目标
- 组内 position(item_group_member 不动,方案 A 否决);
- 甘特行序、表格视图排序(各自体系不变);
- 多套具名看板视图(228 另票);
- 列间排序语义(列序 = workflow position,不变)。

## 二、术语

| 术语 | 义 |
|---|---|
| board order | 项目 × item 的看板排序记忆(position INT);无行 = 未排过 |
| 列内排序键 | boardOrder ASC(有行)→ number 自然序(无行,沉底) |

## 三、数据语义

- 新表 `board_item_order`:`id identity` / `object_id uuid unique` / `project_object_id` FK project / `item_object_id` FK item(双 cascade)——**行存在 = 该 item 在看板上且已有列内位次**;backlog 不留行;
- `position int not null check (position >= 0)`;无列内唯一约束(允许空洞/重复,写入端全列重排保证单调);
- **每列独立序列(用户拍板 2026-11-26 ①)**:排序键 = 同列内 position ASC → number(无行沉底);跨列不比较;
- **生命周期(用户拍板 2026-11-26 ①②③)**:
  - 状态迁移(拖列/详情/CLI PATCH):item 已有行 → 重置为新列**末尾**(该列 max+1);同批迁移按提交序依次 max+1,**相对顺序保持**;无行 → 仍无行,沉底按编号;手工重排后以手工为准;
  - 退出看板回 backlog(移出 active sprint / 看板二元 off):**删行**;
  - 新 item 进看板:不建行,缺省排当前列**末尾**(无行沉底,零钩子);
  - item 转 FINAL:仍留看板(Done 列),行随迁移规则走;
- **写入语义(按列全列重排)**:`PUT /api/projects/{key}/board-order`,body `{ "status": "In Progress", "orderedItemIds": [uuid...] }` = 该 status 列全部 item 的新顺序;服务端校验 status 属于项目、itemIds 均属本项目(否则 400);重写这批 item 的 position(0..n-1,已有行 update,无行 insert);**删除范围 = 当前 status 等于该列且未列入 payload 的既有行**(其它列的行不动);
- **读语义**:`GET /api/projects/{key}/items` 的 ItemDto 增 `boardOrder: Int?`;排序在前端做(键:boardOrder ?? ∞ → number);
- CLI 同能力:YPJ-273 另票,238 后紧接。

## 四、分支真值表(看板 × 拖拽 → 行为)

| 场景 | 行为 |
|---|---|
| 同列:拖 A 到 B 卡上 | A 插到 B 后(占 B 位,B 及其后顺延);PUT 全列新序 |
| 同列:拖 A 到列空白区 | 现状语义=无操作(列空白 drop 是跨列迁移入口) |
| 跨列:拖 A 到他列**空白** | 状态迁移(现状);有行 → 重置为新列末尾(max+1) |
| 跨列:拖 A 到他列 B 卡上 | 状态迁移 + 插到 B 后(PUT 一次带新列全序,PUT 位次为准) |
| 状态迁移(详情页/CLI PATCH) | 有行 → 新列末尾 max+1;同批迁移按提交序保持相对序 |
| 退出看板回 backlog | 删行 |
| 新 item 进看板 | 不建行,缺省列尾(沉底) |
| 无 order 行的列 | number 自然序(现状) |
| item 转 Done/删除 | Done 列照排;删除行级联清(cascade) |

## 五、验收标准

- [ ] 同列拖拽重排后刷新,顺序保持;未拖过的票沉底按编号;
- [ ] 跨列拖到卡上 = 迁状态 + 落位(一次操作两语义);
- [ ] PUT 传不属项目的 itemId → 400 统一错误形状;
- [ ] 删除 item 后 order 行级联清,无残渣(integrationTest 断库);
- [ ] api.http 增 board-order 用例(REST 变更连动手测脚本);
- [ ] 既有看板 e2e 回归绿 + 新增重排 e2e。

## 七、详细设计(代码级修改计划)

### 7.1 现状审计

- 看板列 = status 列;列内序 = API 返回序(`OrderByNumber`,自然序),前端无排序;
- `item_group_member` 无 position;看板混自由 item(`onBoard`,不挂组)→ 方案 A 体验残缺,拍板方案 B;
- 看板拖拽现状:卡片 `draggable` + 列级 `onDrop` = 跨列状态迁移(`moveTo`),无列内重排;
- REST 契约:`GET /projects/{key}/items` 返回全量 ItemDto(看板/表格/回收站共用)。

### 7.3 拖拽语义细节(前端)

| 动作 | 结果 |
|---|---|
| drop 在卡片上(stopPropagation) | 同列=列内重排;跨列=迁状态+落位 B 后;一次 PUT |
| drop 在列空白 | 现状:仅状态迁移,顺序不动(新列沉底) |
| 拖拽预览 | 不做实时 ghost 重排(零依赖原生 HTML5,drop 后 load 刷新;否决 dnd-kit/MUI DragDrop:引依赖换不动收益) |
| 乐观更新 | 不做,PUT 后 `load()`(看板刷新 <300ms,可接受;否决:双写状态源易漂移) |
