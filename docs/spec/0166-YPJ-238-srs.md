## 一、目的与范围

看板 status 列内的 item 顺序可由用户手工拖拽排定并持久化;排序是**看板视图级记忆**(方案 B:项目 × item 粒度),与组/sprint 归属脱钩——换组、rollover 后顺序不跟随。

### 1.1 非目标
- 组内 position(item_group_member 不动,方案 A 否决);
- 甘特行序、表格视图排序(各自体系不变);
- 多套具名看板视图(228 另票);
- 列间排序语义(列序 = workflow position,不变)。

## 二、术语

| 术语 | 义 |
|---|---|
| board order | 项目 × item 的看板排序记忆(position INT);无行 = 未排过 |
| 列内排序键 | boardOrder ASC(有行)→ number 自然序(无行,沉底) |

## 三、数据语义

- 新表 `board_item_order`:`id identity` / `object_id uuid unique` / `project_object_id bigint FK project` / `item_object_id uuid`(寻址经 item.object_id)/**不以 FK 束 item**(item 物理删级联不设;deleted item 行留存无害,查询侧 join 过滤)——实现按仓内惯例 FK 束 `item(id) on delete cascade`,`project(id) FK`;
- `position int not null check (position >= 0)`;无唯一约束(position 允许空洞/重复,以写入端全列重排保证单调);
- **写入语义(全列重排)**:`PUT /api/projects/{key}/board-order`,body `{ "orderedItemIds": [uuid...] }` = 该列(该 status)全部可见 item 的新顺序;服务端按 0..n-1 重写这批 item 的 position(已有行 update,没有行 insert),**不在列表内的既有行删除**(防僵尸);item 不属该项目 → 400;
- **读语义**:`GET /api/projects/{key}/items` 的 ItemDto 增 `boardOrder: Int?`;排序在前端做(键:boardOrder ?? Infinity → number);
- 新建 item 不写 order 行 → 沉底;显式拖一次即入册。

## 四、分支真值表(看板 × 拖拽 → 行为)

| 场景 | 行为 |
|---|---|
| 同列:拖 A 到 B 卡上 | A 插到 B 后(占 B 位,B 及其后顺延);PUT 全列新序 |
| 同列:拖 A 到列空白区 | 现状语义=无操作(列空白 drop 是跨列迁移入口) |
| 跨列:拖 A 到他列**空白** | 状态迁移(现状),order 不变(新列里沉底) |
| 跨列:拖 A 到他列 B 卡上 | 状态迁移 + 插到 B 后(PUT 一次带新列全序) |
| 无 order 行的列 | number 自然序(现状) |
| item 转 Done/删除 | Done 列照排;删除行级联清(cascade) |

## 五、验收标准
